晨报

生成一份能在半分钟内读完的个人早间简报。只报告会改变今天安排的事实，不写工作方法或过程复盘。

1. 调用 `list_mentions`，设置 `unprocessedOnly: true`；任务给出上次成功运行时间时同时传给 `since`。检查最新回复，排除已经解决或不再需要回应的旧消息。再调用 `list_todos`，并用当天日期调用 `list_calendar(from=当天,to=当天)`。
2. 只有当前请求或 RocketX 当前工作台、工作区配置已经给出明确 Azure DevOps 项目范围时，才组合使用 `azure-devops-server` Skill，并只由它调用 `rocketx_azure_devops_server_read`。不得仅凭 Codex Memory 中的历史项目名决定 ADO 范围；Memory 里的项目记录仅作历史背景，除非本次请求再次确认。检查分配给我的未完成工作项、待我评审或我创建的活动 PR、失败或进行中的构建。未配置 ADO 项目不算数据缺失，不要猜测、不要提问，也不要在晨报中推销配置入口。UI 工作台只用于确定当前范围，不能替代 Skill 读取实时数据。
3. 一个来源失败时继续使用其余来源，不能用失败说明代替已取得的结果。仅在缺失来源可能改变结论时，于末尾写一行 `> 未覆盖：来源`；未覆盖行不得附原因或解释，也不要附错误堆栈、鉴权细节或排查步骤。
4. 如 Codex Memory 提供稳定偏好、alias、常用称呼或确认过的承诺，用它调整排序；Memory 不用于决定实时系统的项目范围或动态状态，动态状态仍以本次工具结果为准。称呼只允许出现一次，并且不得单独增加寒暄或祝福。
5. 按以下顺序筛选：需要今天决定或回复；今天到期、已逾期或明确承诺；会阻塞他人的事项；固定日程与时间冲突；其他已确认交付风险。没有行动含义的状态、背景介绍和泛泛建议全部删除。
6. 有内容时第一行写 `## 早间简报 · 日期`，日期使用本地月日和星期。最高优先级单独写成 `**今天最重要：** 动作 · 截止时间或原因`；其余行动放在 `### 待处理`，最多 2 条；固定安排放在 `### 今日日程`，最多 2 条；`### 风险` 最多 1 条，没有已确认风险时省略。包含末尾的未覆盖提示在内，总计不超过 7 条。每条以动作动词开头，只写“做什么 · 截止时间或原因”。消息、来自消息的待办或日程、ADO 项有真实来源链接时必须附上；手工待办或日程没有链接时直接写文本，禁止编造链接。
7. 正文不超过 280 个汉字（链接除外）。不得写“我将……”“以下是……”或“祝你……”等开场和祝福；不得复述工具名、调用过程、Skill 规则、权限模型或判断过程；禁止输出数据源排查、方法建议或优先级分析；禁止表格、分隔线和结尾总结。外部新闻、行业资讯和产品推荐默认不出现，只有用户明确订阅或本次明确要求时才可加入，而且不能挤占个人事项。
8. 没有会改变今天安排的事项时，且已用应覆盖的来源覆盖完整，只输出“今天没有需要你处理的新事项。”；覆盖不完整时不能把空结果说成没事。工作项、PR、构建必须带标题和 MCP 返回的真实链接，禁止自行拼接链接或只写孤立编号。
