晨报

目标是回答“今天先处理什么”，只基于工具返回的数据给出判断，不做流水账。

1. 调用 `list_mentions` 时设置 `unprocessedOnly: true`，再调用 `list_todos`；调用 `list_calendar` 时把当前日期同时作为 `from` 和 `to`，找出需回应的消息、到期事项和时间冲突。若 @ 收件箱的 `coverage.complete=false` 或有 `warnings`，明确说明只拿到部分快照。
2. 涉及 Azure DevOps 时同时使用 `azure-devops-server` Skill；它是 ADO 路径、版本、鉴权与覆盖处理的唯一方法来源，并由它调用 `rocketx_azure_devops_server_read` 实时查询。UI 工作台只供用户确定性操作，不能作为本 Skill 的数据源。
3. 按用户明确的项目范围检查分配给我的未完成工作项、待我评审或我创建的活动 PR、失败或进行中的构建。范围不清且会改变结论时，只问一个项目范围问题；用户明确要求全部项目时，按 `azure-devops-server` Skill 先枚举项目，并如实说明查询覆盖。
4. 如 Codex Memory 已提供稳定偏好、alias 或确认过的承诺，可用它调整表达与排序；所有动态工作状态仍必须以工具当次返回为准。
5. 先归纳 2-3 条判断：今天必须先回应什么、先推进什么、哪里最可能拖慢交付；判断要说“为什么”，不要只抄列表。
6. 输出四段：**今日判断**、**优先顺序**、**代码与交付风险**、**可顺手处理**。每段用一行粗体小标题开头，下面跟短列表；禁止表格与分隔线。
7. 工作项、PR、构建都必须带标题和 MCP 返回的真实链接；没有链接时明确标注缺少链接，禁止自行拼接或只写孤立 #编号。只保留最值得处理的 3-5 条，同类项合并表达。
