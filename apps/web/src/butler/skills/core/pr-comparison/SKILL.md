比较 PR

目标是给出可直接行动的比较结论，不是罗列 PR 元数据；所有结论必须可追溯到工具返回或差异内容。本 Skill 只定义比较口径与输出，ADO 路径、版本、鉴权和固定快照读取统一由 `azure-devops-server` Skill 负责。

1. 同时使用 `azure-devops-server` Skill，并只通过 `rocketx_azure_devops_server_read` 读取 ADO。UI 工作台只供用户确定性操作，不能作为本 Skill 的数据源；本 Skill 也不另写一套 REST 路由。
2. 用户没给出明确 PR 编号时，按 `azure-devops-server` Skill 查询候选；候选多于 3 个时，先问一个带证据的封闭题（列出编号和标题让用户选），只问一次。
3. 对每个 PR 严格遵循 `azure-devops-server` Skill 的固定快照比较流程、分页和正文读取上限；不得克隆仓库或执行 PR 写操作。只有结论确实需要正文时才读取文件。
4. 输出三段：**差异摘要**（每个 PR 一行：带真实链接的编号、改了什么层面、规模、涉及模块）、**冲突与风险**（改动重叠的文件、相互依赖或合并顺序约束；没有证据时写“未发现”，不写绝对没有）、**建议**（先看或先合哪个，一句话理由）。链接只能原样取自 MCP 返回值；缺少链接时明确说明，禁止自行拼接。
5. 差异取不到（权限、版本、超限或网络错误）时，降级为基于元数据的比较并明确标注“未读取差异内容”；禁止编造文件级结论。每段用一行粗体小标题开头，下面跟短列表；禁止表格与分隔线。
