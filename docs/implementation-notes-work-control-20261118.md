# 工作控制与并行实施记录

计划：`.omx/plans/work-control-implementation-20261118.md`。承接用户确认的可控看板与多工作目录隔离，不用新原型代替产品实现。

## 决定

- 四列看板作为主入口；当前工作在同页辅助区操作，复用原生工作合同。
- 新可写任务不再静默落入当前/默认工作区；显式目录或原工作绑定优先。
- 本批不使用真实Key/会话、不外部写入、不动用户运行实例、无新依赖。

## 偏离

- 编译资源确认曾误把上批内部3GiB上限当成需用户再次审批的条件。复核用户指令与历史记录后撤回这项不必要确认，依据本轮明确开发授权执行常规隔离编译。前序预算不改写；本批另设新增1GiB上限、C至少3GiB空闲、单通道复用C缓存，越界终止自有编译进程，不清缓存、不写D target、不改用户实例。

## 发现

- `omx explore` 在本机启动失败（无法定位allowlist wrapper所需host bash），按仓库约定回退直接rg/源码读取。
- `superAgentBridge::resolveBaseRepoRoot` 当前会回退到当前/default/butler工作目录；对于新可写工作不足以证明项目归属。
- 当前Board默认纵向分组并在选中后隐藏列表，尚未实现已经确认的四列控制主视图。
- 原生资源准入与预算由独立只读审计核对，尚未运行本批Cargo。
- 四列和现场组合复查发现工作位置独占一行时940×640选择框被压缩，仅37.5%可见。移入现有元信息行后，默认/长问题、固定输入与实际点选完整通过。原生Scene组合25/25；最新固定源组合将在最终复验。
- 独立复查发现宽窗被覆盖控件可聚焦、隐藏卡片导致快照缓存过时、迟到保存清空新草稿，已交前端负责人以真实复现用例修正。
- 后台静态复查抓出明确拒收不释放、preclaim崩溃锁死、snapshot历史终态掩盖下一已认领写入等问题。新增OS生命周期证据与精确恢复闭环，仍须本批真实编译/运行验证。

## 待验证

真实桌面三项工作调度旅程受磁盘空间阻塞，尚未运行；其结果与浏览器模拟 IPC、原生单元测试分开登记。新工作自动建立原生执行线程、重工具串行、端口/测试库隔离仍不属于已完成能力。

## 原生资源准入与恢复

- 新增安装实例级 Host 资源登记，使用 SQLite 即时事务限制最多两项原生写入；canonical 路径、Windows 大小写/目录别名及父子目录互斥。工作正文和凭据仍留在原账号库。Prompt 在 outbox 认领前申请；等待保留 prepared，不扣自动轮次，不当作失败。
- 停止与同轮调整复用原轮次归属，不额外占槽；审批、未知投递及断线不释放。只有持久未发送/明确拒收事实，或匹配原 owner/generation/turn 的实际终态才能释放。
- 新连接保存 Windows 独占生命周期文件句柄。崩溃恢复核对原版本化 owner marker、旧句柄已释放、原线程/目录和真实 idle；snapshot 恢复先排除所有未结 writer，再检查历史轮次。缺失可验证旧归属且无原轮次的 legacy unknown 保守保留占用。
- 独立原生审计发现的三项问题已关闭：明确拒收槽泄漏、preclaim 崩溃后永久占用、历史终态掩盖下一条已认领但未发送的写入。独立复核源码指纹、产物 hash 与测试日志后通过。
- 实际 Rust 编译成功，新增准入 **15/15**、恢复闭环 **6/6**；最终完整测试程序 **381 通过、11 ignored、1 filtered**。被过滤的是与本批无关的大体积发布归档解压检查，不登记为通过。证据位于 `.omx/logs/work-control-20261118/native-tests-*` 和 `native-control-unit-artifact.json`。

## 验证偏离与资源记录

- 原生首编译发现已有 C 缓存缺少 libsqlite3 bindgen：从原 D 缓存只读复制同版本生成文件到 C，并校验与依赖内置源 hash 一致；没有修改依赖或清缓存。其后真实编译发现一处 Option 类型错误，修复后重编译通过，红灯 stderr 保留。
- 第一次全量测试的工作目录错误导致两个资源相对路径测试失败；修正测试启动目录后 ADO 组 **11 通过、1 ignored**，最终全量包含这两项均通过。
- 另一次全量遇到旧发布包解压，触及 C 盘 3GiB 空闲线而终止自有测试进程。精确临时 fixture 的清理被自动审批拒绝（仅返回 blocked by policy），没有绕过删除。改用 NTFS 无损压缩本批自有 fixture 和调试符号，保留全部文件；关键文件压缩前后 hash 一致。后续全量显式跳过该大归档检查，磁盘门槛不降低。
- 原生桌面验收 GUI 复用同一 C 缓存，省去第二份 PDB；单元产物与符号仍保留。首次链接和压缩本批输出后的原目录重试，均在 C 空闲低于 3GiB 时由 guard 终止。未完成的 executable 不作为可运行产物，不宣称 GUI 构建或真实多工作验收通过。新 app ID 的启动和合成 seed 均未执行。
