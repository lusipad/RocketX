# 管家逐项体验验收与发布计划

日期：2026-07-27  
目标版本：`v0.33.3`  
状态：代码与本地安装包门禁完成，待公开发布

## 目标

管家应像一个克制、可靠、连续的工作伙伴，而不是聊天窗口、任务仪表盘或执行控制台。用户在一张纸上看到真正需要处理的事；临时问答、完整对话、房间上下文和后台派活共享同一套持久状态，并在失败时给出可理解、可恢复的反馈。

## 已确认的产品判断

- 管家是独立一级入口，不与“消息 / 待办 / 日历”混在同一组，也不恢复“执行间”。
- 主页面保持一页化；次级内容优先用折叠、小图标、轻动画和小按钮原位处理。
- 完整对话采用管家居左、用户居右的双侧气泡。
- 房间管家是当前房间的上下文浮层，不是全局管家的缩小版；打开完整对话时必须保留当前会话和来源。
- 临时问答离开页面后仍可回看；多轮讨论不能只保留一轮。
- 汇总、提醒、待办和在办事项必须有真实数据来源、明确空态与失败重试，不能用永久转圈掩盖错误。
- 管家只投影既有状态，不新增第二套任务、会话或 Agent Runtime。

## 验收矩阵

1. **入口与导航**
   - 管家入口分组、选中态、键盘访问、窄窗口与返回路径。
2. **今日纸面**
   - 日期切换、真正空态、待确认、在办、待办、今日汇总、消息与提醒、临时问答。
3. **完整对话**
   - 新建/切换/删除会话，多轮历史，左右气泡，草稿与附件，离页返回，运行/错误/取消。
4. **房间管家**
   - 打开/关闭、宽度、遮挡、房间来源隔离、历史连续、全屏往返、键盘与焦点。
5. **例行事务与能力库**
   - 装载、暂停、恢复、编辑、删除、手动运行、预检无事、投递汇总、失败重试。
6. **后台任务与闸门**
   - 排队、运行、等待审批、等待输入、失败、恢复、取消、幂等与重启恢复。
7. **历史与持久化**
   - 刷新、离页、重启、跨日期、旧版本数据与无可靠房间来源的保守降级。
8. **可理解性与视觉**
   - 首屏层级、信息密度、可点击性、颜色语义、动效、空态文案、1080p 与窄窗口。
9. **发布合同**
   - 版本一致、变更日志、全量测试、Windows slim/full 两包、full 不含 `codex.exe`、签名、Updater、插件包、SHA256 与 Latest 策略。

## 执行与验证

1. 先对真实渲染界面建立基线并保存截图，不从源码猜体验问题。
2. 对每个行为缺陷先补可复现回归，再做最小修复；视觉问题优先用现有 token 和组件解决。
3. Butler 专项通过后运行全仓类型检查、纯测试、回归、UI、生态、smoke、Rust 与生产构建。
4. 在项目内运行桌面端完成真实账号 dogfooding，并本地生成、检查两个 Windows 安装包。
5. 合入 `main` 后创建不可变标签，等待并验证公开 Release 的资产、校验和与 Latest 状态。

## 偏差规则

- 若完整对话与房间浮层无法共享同一会话，优先修状态合同，不在组件里复制历史。
- 若主动能力没有可靠来源或成本守卫，明确显示未启用/无新事，不伪造“已整理”。
- 若视觉空间不足，先折叠次要解释、缩短按钮文案或减少元数据，不隐藏真实事项。
- 不扩大文件、网络、命令权限；不引入新依赖；不恢复执行间或第二 Agent Runtime。
- `v0.33.1` 已被一次提前标签占用且被发布门禁拒绝；`v0.33.2` 又在本轮验收完成前被提前打标并取消构建。不可变标签均不改写，正式发布顺延为 `v0.33.3`。
