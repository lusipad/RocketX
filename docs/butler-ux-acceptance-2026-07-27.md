# 管家人用体验验收

日期：2026-07-27  
范围：管家纸、完整对话、房间管家、汇总与提醒、待办持久化  
结论：通过，进入 `v0.33.3` 发布门禁

## 产品结论

管家最合适的形态不是另一套聊天、任务面板或执行控制台，而是“一张安静的纸 + 需要时展开完整对话 + 房间里的轻量浮层”。

- 管家继续作为独立入口，与消息、待办、日历分组隔开；不恢复执行间。
- 纸面只投影真实待办、在办、待确认、汇总与提醒。没有内容时诚实留白，不造推荐卡片。
- 次要说明和运行细节默认折叠；常用动作使用小图标或短按钮原位完成。
- 完整对话保留微信式双侧关系：管家在左、用户在右。
- 房间管家只看当前房间，浮层宽度可调；全屏进入同一段完整对话并保留房间工作面。
- 临时问答属于发起当天和当前 Butler 会话。离开模块再回来仍在，但不会串到另一张日期纸。
- 失败必须原位说明并可重试；重试不算新一轮，不会因为网络失败意外升级完整对话。

## 真实桌面验证

在项目内启动 Tauri，使用真实 Rocket.Chat 账号完成：

1. 管家纸显示真实逾期待办、来源、汇总和提醒，不再误画空纸。
2. 纸上询问“你是谁？请一句话回答。”后得到实际 Butler 回复；切到消息再回来仍能看到这一轮。
3. 在 `general-test` 房间连续询问房间名称和最近一条消息，第二轮得到带来源的回答。
4. 关闭房间浮层再打开，两轮问答都保留。
5. 从房间浮层全屏进入完整对话，页头显示“当前工作面：general-test”，历史以左右双侧气泡呈现。
6. 运行日志没有未捕获错误；仅保留既有的两个 Rust `dead_code` 编译警告。

## 本轮修正

- 临时问答状态从页面局部状态提升到运行期 UI store，离开模块不丢。
- 临时问答按日期和 Butler 会话隔离，错误绑定原问题，不受后续完整对话覆盖。
- 增加原位错误与“再试一次”；重试保持原轮次。
- 房间全屏入口在模块切换完成后写回房间上下文，避免恢复流程覆盖。
- 增加房间宽度键盘行为、例行事务刷新持久化和 Todo DB 直接测试。

## 有意不做

- 临时问答不写入新的长期数据库；完整历史仍由既有 Butler 会话持久化。
- 不新增第二套房间会话、任务模型或 Agent Runtime。
- 不加入新的依赖、推荐卡片或执行控制面板。

## 非阻塞观察

`pnpm test:classify` 在当前共享测试服务器上遇到 3 个历史 `t=d` 会话成员数不符合探针假设，并触发上游 libuv 断言。该探针不属于 Butler 或发布门禁，未通过修改产品代码掩盖；其余 Butler、全仓回归、真实服务 smoke、Rust 和构建门禁独立验证。
