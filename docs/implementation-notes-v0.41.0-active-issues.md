# v0.41.0 活动 issue 实现记录

发布日期：2026-08-12

## 已解决问题

- #276：开机自启改由受控的 Rust 命令维护，只允许正式安装目录中的可执行文件写入注册表；登录启动使用 `--autostart` 静默进入托盘，普通二次启动会唤醒已有窗口。
- #299：会话定位到末尾后固定观察四个动画帧，覆盖首帧后继续增长的消息内容，避免提前结束滚动收敛。
- #304：可信本地目录及 UNC 更新允许无 Minisign 签名；HTTP 和 GitHub 更新仍强制签名。候选包从探测、等待主进程退出到暂存安装的每个阶段都校验同一 SHA-256，阻止替换攻击。
- #305：深色引导卡片统一使用固定的深色背景和高对比度文字、焦点样式，三个步骤均通过 WCAG 对比度检查。
- #306：Windows WebView2 在隐藏、最小化及失焦时调用官方低内存目标 API，恢复显示或聚焦时切回正常目标；未使用不受支持的浏览器启动参数。
- #307：“我的贡献”更名为“贡献概览”，默认日期范围改为滚动的一整年，同时保留分页、并发上限、缓存和取消机制。

## 关键约束

- 无签名更新只适用于用户明确选择的本地目录或 UNC 目录；远程更新的发布者身份验证没有放宽。
- SHA-256 固定用于防止本地候选包在安装流程中被替换，不等同于发布者签名。
- 开发及构建目录中的桌面可执行文件不能注册开机自启，避免污染开发机登录项。
- WebView2 仅调整内存目标，不暂停后台脚本和连接。
