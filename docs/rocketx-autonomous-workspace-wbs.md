# RocketX 自主工作系统 WBS 计划

版本：1.0。日期：2026-11-17。状态：首版执行计划，开发工作包初始均为待盘点/待实施，尚未按本计划验收。配套：[完整方案](rocketx-autonomous-workspace-design.md)。

本计划把目标拆成可独立交付、可检查依赖和证据的工作包。现有代码、测试和历史构建可复用，但需要按新目标复核后才能登记完成；文档编写完成不等于以下研发工作包完成。

2026-11-17 已开始执行，实际状态与证据见[实施进度](rocketx-autonomous-workspace-progress.md)。下文“初始”描述计划发布时的状态，不覆盖进度记录。用户本轮明确暂不做外部写入，外部真实联调后置，本机开发和隔离验证继续。

2026-11-18 控制看板、显式目录绑定及原生两槽/目录互斥已进入产品源码；本批完成与剩余范围见[工作控制实施记录](implementation-notes-work-control-20261118.md)。它们落实 W06.01 与 W04.05/W08.01 的部分验收，不关闭自动新建原生线程、重工具/端口隔离、长时间运行或外部交付等父包剩余项。

## 1. 范围和执行约定

首版交付 Windows 本机的 Pi 管家＋Codex 原生执行主路径、同页工作现场、可信总结、持久调度、Bug 主动调查、ADO 与 GitHub、独立验证和授权内交付。虚拟机、多节点、远程执行池排除；语音、独立于整个应用退出后仍工作的常驻服务及其他提供方的新增完整控制，列为后续/可选项。保留已有非核心提供方的兼容行为。

本机独立验证使用另一个 checkout、测试账号及测试数据，不要求 VM。能力不足、真实测试环境缺失或外部版本不兼容时保留待验证/阻塞状态，不用模拟结果抵消。

### 工作包字段

- Wxx.yy 是稳定叶子工作包 ID；父级 Wxx 用于归组，不作为可执行依赖。
- 依赖为完成后才能开始该工作包的强依赖；可先读代码和准备材料，但不得绕过前置门禁宣称完成。
- S：单一边界、已有模式；M：多个相关模块和失败分支；L：高不确定性或跨生命周期。它们是相对规模，不是人日承诺；L 开工前再拆成小 PR，并保留父工作包完整验收。
- 责任角色指定责任范围，不代表已分配到某个人/Agent；执行时指定一名负责人和独立验收者，不能由多个 Agent 同时修改一个工作包的同一分支。
- 表中的验收文字是特定要求，另须满足第 5 节通用完成定义。Rxx/AC-xx 对应方案第 18 节。

### 状态与记录

所有叶子初始状态为 `待盘点`。盘点后依次为 `就绪 → 进行中 → 待验证 → 已验收`；存在明确外部前提时记 `受阻` 并写解除条件。没有新证据的历史实现不能直接跳至已验收。

执行记录保留：负责人、原始/当前状态、分支/PR、依赖检查、预期产出、实际变更、验证者、构建/提交、证据路径、剩余问题、最后更新时间。未通过检查记入原工作包，修复后复验，不另建重复任务粉饰失败。

阶段是可演示成果，不是按文件数量统计的完成百分比。工作包依赖为强约束；某一门禁失败时，独立工作包可继续，依赖失败事实的工作包暂停。

建议执行波次：

1. **证据与原型**：W01 完成后，W02 的原生探针、桌面驱动、Host 探针和体验原型可并行；W03.01/03.05 可同步准备。

3. **管家与自主推进**：W07、W08；同时推进已满足依赖的 ADO/GitHub 连接器和验证工具。

## 5. 完成定义和证据

一个工作包标为已验收需同时具备：

1. 依赖已验收，或依赖明确产出的受限能力决定已被该包落实；实现不扩大未授权范围。
2. 本包特定完成条件成立，相关失败分支经过验证，代码/文档与真实行为一致。
3. 证据绑定当前 commit/build、要求版本、环境和执行时间；修改后受影响旧证据作废。
4. 独立验收者给出通过、受限或失败结论；受限能力不能计入不受限目标。
5. 用户可见行为能通过真实入口操作；内部 setter、模拟 ready 或静态截图不能替代原生执行证据。
6. 已知阻碍与残留工作有归属；没有把依赖失败改写成“已完成，等以后验证”。

证据建议放在任务专属目录，记录 `workPackageId / requirementIds / commit / buildHash / environment / commandsOrSteps / expected / observed / artifacts / reviewer / limits`。用户产物与测试截图分开。采用现有测试、类型和架构命令；正式新增工具按方案 §13.2 实施，不假装建议的 `doctor/drive` 命令已存在。

复用基础命令：`pnpm typecheck`、`pnpm check:architecture`、针对性的 `pnpm exec tsx --test ...`、`pnpm exec playwright test ...`、适用的 Rust tests、原生 smoke 与 `pnpm build`。具体命令、提供方版本和测试输入在工作包启动记录中冻结。没有配置 lint 脚本的部分不能在报告中虚称 lint 通过。

首版总验收：AC-01–AC-18 全部有结果，必须交付项均通过；按能力开放项有真实矩阵和符合该矩阵的交互；后置项不计入完成率。真实外部测试缺环境/权限时，相关工作包保持受阻，不通过隐式访问生产数据解决。
