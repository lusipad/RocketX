# `WB` 工作台与 Azure DevOps

> 当前状态：`受限可用`
> 基线：工作树 `2026-08-09`
> 平台：桌面端与网页版，能力受 ADO 连接和认证方式限制

## 1. 目标

工作台是用户直接掌握的确定性界面，用于查看和修改 Azure DevOps 中的权威计划、查询与工作项。自然语言管家可调用对应 Skill，但不能用对话中的推测替代工作台事实。

## 2. 范围

### 包含

- ADO 连接配置、连通性和项目加载；
- 个人工作、团队查询、自定义查询和刷新；
- Epic / Feature / Story / Task 等计划层级与详情；
- 工作项创建、字段更新、负责人/状态调整等显式写操作；
- 工作项链接、来源和失败反馈；
- 从工作项创建 Rocket.Chat Discussion 并可选择本地 Agent 环境。

### 不包含

- 在本地维护一套与 ADO 脱离的影子计划；
- 把 AI 摘要当作完整工作项列表；
- 对结果未知的写请求自动重试；
- 承诺浏览器支持 NTLM/Windows 集成认证。

## 3. 入口与前置条件

- 顶部“工作台”进入确定性 ADO 页面。
- 设置中配置 ADO 地址、认证类型和个人凭据；团队配置可提供非敏感默认端点。
- 当前账号必须在 ADO 中具有对应项目和工作项权限。

## 4. 主流程

1. 用户配置连接并刷新，工作台验证端点后读取可见项目和查询。
2. 用户选择“我的工作”、迭代/计划视图或自定义查询，页面直接展示 ADO 返回的列表与层级。
3. 用户打开工作项查看编号、标题、类型、状态、负责人、父子关系和来源链接。
4. 写操作先在确定性表单中展示目标与字段；用户触发后提交一次。
5. 成功时使用服务端返回或重新读取的版本更新界面；冲突或结果未知时停止并要求刷新确认。
6. AI 查询 ADO 时必须走标准 Skill/工具，并将可验证结果和来源回到任务；工具失败不得把 `@Me` 快照当成全组织结果。

## 5. 状态与交互

- `未配置`：给出设置连接的入口。
- `连接中/刷新中`：保留上一份数据并标记其可能过期。
- `空结果`：只说明当前查询为零，不扩展为项目/组织没有工作项。
- `写入确认`：展示即将变化的字段和目标工作项。
- `冲突`：说明版本已变化，要求刷新后重新决策。
- `结果未知`：明确不能判断写入是否成功，禁止自动重复提交。

## 6. 平台与依赖

| 场景 | 当前状态 | 行为 |
| --- | --- | --- |
| 桌面端 + PAT/支持的认证 | 受限可用 | 通过本地适配器或 HTTP 访问 ADO；可尝试 NTLM 场景 |
| 网页版 + PAT/同源可达 | 受限可用 | 受 CORS、网络和浏览器认证限制 |
| 网页版 + NTLM | 不适用 | 浏览器不能按当前实现提供本机 NTLM 适配 |
| 未配置/无权限 | 不可用 | 工作台保留设置和诊断入口，不显示伪数据 |

## 7. 数据与同步

- 项目、查询、迭代和工作项以 ADO 服务端为真源。
- 端点、认证类型、工作台布局和最近选择保存在本机；个人凭据不进入团队配置。
- 列表缓存仅用于恢复界面，刷新后必须以 ADO 返回校准。
- 写操作应携带服务端修订信息或在写后读取；不能用本地最后写入覆盖未知的新版本。

## 8. 权限与安全

- PAT 等凭据只用于用户配置的 ADO 端点，不写入日志、团队配置或 AI 提示正文。
- 用户可见的查询与写权限由 ADO 最终裁决。
- AI 访问 ADO 必须通过已安装/启用的标准 Skill 与受控工具，不能从任意 shell 重造接口。
- 所有结构化写操作必须保留明确目标；高风险或越权操作由权限/审批层处理。

## 9. 失败与降级

| 场景 | 用户可见结果 | 副作用与恢复 |
| --- | --- | --- |
| 授权失败 | 显示连接或权限错误 | 不把空数据解释为零；检查端点/PAT 后重试 |
| 查询只返回局部范围 | 显示实际查询范围 | 不宣称覆盖整个组织 |
| 写入版本冲突 | 显示冲突并停止 | 刷新最新修订后由用户重新提交 |
| 写请求超时/断线 | 标为结果未知 | 先读取工作项确认，禁止直接重试 |
| 工具无来源链接 | 结果标注不可引用/待确认 | 不输出伪链接或“可信总数” |

## 10. 验收标准

- `WB-AC-01`：未配置 ADO 时工作台显示可操作的设置入口，不显示示例计划冒充真实数据。
- `WB-AC-02`：查询为空时文案包含查询范围，不能推断组织总量为零。
- `WB-AC-03`：工作项列表和详情包含可回到 ADO 的来源标识或链接。
- `WB-AC-04`：任何写操作只提交一次；结果未知时必须先读回确认。
- `WB-AC-05`：版本冲突不会静默覆盖服务端新值。
- `WB-AC-06`：AI 对 ADO 的自然语言任务通过标准 Skill/工具执行，工具失败时给出真实失败原因。

## 12. 已知差距与目标

- 各 ADO Server 版本、认证代理和企业策略差异较大，发布前仍需用目标服务器做真实读写验证。
- 网页版不提供 NTLM 替代路径；需要 PAT、反向代理或服务端网关才能覆盖该场景。
