## 1. 场景定义

| 场景 | 定义 |
| --- | --- |
| 桌面端 + 兼容 Codex | Tauri 桌面端可解析已登录的 Codex，`app-server` 探测和版本门禁通过 |
| 桌面端，无可用 Codex | 未安装、未登录、版本被阻止，或 `app-server` 探测失败 |
| 桌面端 + 可用 DSH | slim 可连接已安装且可运行、且已被 RocketX 验证为 `0.2.1-rc.2` 的系统 DSH；Windows full 则使用同样锁定为 `0.2.1-rc.2` 的私有固定 DSH 运行时；发送时已配置当前所选 provider 需要的凭据 |
| 网页版 | 浏览器访问 RocketX，不具备 Tauri 本地进程与文件能力 |
| 性能模式 | 用户主动关闭 Codex、DSH、例行任务、共享 Agent、本地 OCR 等高开销能力 |

矩阵中的“受限”表示功能存在，但还依赖服务器设置、权限、平台或本机进程；不表示功能缺失。

桌面端的 AI 能力共享同一个启动级选择：Codex、DSH 或无 AI。设置保存后要重启 RocketX 才会生效，当前进程不会热切换，也不会同时启动两个后端。下表里所有 AI 行都按这一前提解释。

## 3. Codex Runtime 兼容结论

| 条件 | 当前表现 |
| --- | --- |
| 未安装 Codex CLI/App | Rocket.Chat 与确定性工作台继续可用；管家本地执行、目录、Memory、已安排执行和本机共享 Agent 宿主不可用；有效远端托管仍可查看并使用 `@ai` |
| 安装版本低于协议基线 `0.144.4` | 被版本门禁阻止，不尝试启动任务 |
| 版本等于已验证基线 `0.144.4` | 标记为 `verified`，完成 `app-server --help` 与登录探测后可用 |
| 版本高于基线 | 标记为 `untested-newer`；轻量探测通过后允许使用，并向用户保留未验证提示 |
| Codex 未登录 | Runtime 可被发现，但 AI 任务不可进入可运行状态 |
| 手动路径无效 | 显示具体探测错误，并继续允许用户改回系统或标准安装路径 |

RocketX 当前桌面安装包采用 slim/full 分层。默认 slim 不捆绑 Codex 或 DSH，只负责探测系统安装；系统 DSH 只有在版本被 RocketX 验证为 `0.2.1-rc.2` 时才可用，更高版本需先升级 RocketX 支持线。Windows full 额外在私有资源目录中安装固定的 Codex 0.144.4、DSH 0.2.1-rc.2、私有 Node 与 OCR。macOS 和 Linux 官方包目前仍是 slim-only。

## 4. DSH Runtime 兼容结论

| 条件 | 当前表现 |
| --- | --- |
| 官方 slim 发现到可运行的系统 DSH | 可启动 DSH bridge，并打开官方 DSH Web 的本地 loopback 页面；AI 托管/共享 Agent 仍通过 controller/host 原生 RPC 交互 |
| Windows full 私有 `@deepseek-ai/dsh@0.2.1-rc.2` 运行时 | 可启动 DSH bridge，并打开官方 DSH Web 的本地 loopback 页面；AI 托管/共享 Agent 仍通过 controller/host 原生 RPC 交互 |
| DSH 不可用 | DSH 后端不可用并显示诊断；不影响 Codex 与确定性界面 |
| 当前 DSH provider 的凭据未配置或无效 | 可以查看 DSH 状态和配置；发送会 fail-closed，并展示 provider 返回的诊断与 DSH 配置入口 |
| 随包 DSH 资源缺失/不完整 | 拒绝启动该后端，不在运行时下载或猜测兼容版本；继续使用通过探测的 Codex，均不可用时以无 AI 启动 |
| DSH bridge 退出 | 清理旧审批/问题/队列，把运行 Session 标为中断；重连后从原生历史恢复 |

正式安装包采用 slim/full 分层：slim 只做系统探测，系统 DSH 必须先通过 RocketX 的 `0.2.1-rc.2` 验证；Windows full 另带私有 DSH 生产运行树和私有 Node。开发环境可通过 `sourcePath` 或 `ROCKETX_DSH_SOURCE` 显式覆盖源码构建；正式运行默认不依赖兄弟源码仓库。

## 5. 规格维护检查

改动下列任一事实时，必须同时更新本矩阵和对应能力域：

- 新增或删除导航入口；
- 改变 Web、桌面端、性能模式或无 Codex 场景的可用性；
- 改变数据落点、审批策略、调度存活条件或版本门禁；
- 改变 Codex/DSH 后端能力、固定 DSH 版本或系统 Node.js 要求；
- 把“未实现/部分实现”提升为“已实现”。
