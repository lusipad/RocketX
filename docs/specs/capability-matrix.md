# RocketX 能力矩阵

> 基线：工作树 `2026-08-12`，应用版本 `0.40.4`
> 判断口径：只记录当前可观察行为；未来目标见各能力域的“已知差距与目标”。

## 1. 场景定义

| 场景 | 定义 |
| --- | --- |
| 桌面端 + 兼容 Codex | Tauri 桌面端可解析已登录的 Codex，`app-server` 探测和版本门禁通过 |
| 桌面端，无可用 Codex | 未安装、未登录、版本被阻止，或 `app-server` 探测失败 |
| 网页版 | 浏览器访问 RocketX，不具备 Tauri 本地进程与文件能力 |
| 性能模式 | 用户主动关闭 AI、例行任务、共享 Agent、本地 OCR 等高开销能力 |

矩阵中的“受限”表示功能存在，但还依赖服务器设置、权限、平台或本机进程；不表示功能缺失。

## 3. Codex Runtime 兼容结论

| 条件 | 当前表现 |
| --- | --- |
| 未安装 Codex CLI/App | Rocket.Chat 与确定性工作台继续可用；管家执行、目录、Memory、已安排执行和共享 Agent 不可用 |
| 安装版本低于协议基线 `0.144.4` | 被版本门禁阻止，不尝试启动任务 |
| 版本等于已验证基线 `0.144.4` | 标记为 `verified`，完成 `app-server --help` 与登录探测后可用 |
| 版本高于基线 | 标记为 `untested-newer`；轻量探测通过后允许使用，并向用户保留未验证提示 |
| Codex 未登录 | Runtime 可被发现，但 AI 任务不可进入可运行状态 |
| 手动路径无效 | 显示具体探测错误，并继续允许用户改回系统或标准安装路径 |

RocketX 当前桌面安装包不捆绑 Codex。全量包比精简包多的是 OCR 等资源，不是 Codex Runtime。

## 4. 规格维护检查

改动下列任一事实时，必须同时更新本矩阵和对应能力域：

- 新增或删除导航入口；
- 改变 Web、桌面端、性能模式或无 Codex 场景的可用性；
- 改变数据落点、审批策略、调度存活条件或版本门禁；
- 把“未实现/部分实现”提升为“已实现”。
