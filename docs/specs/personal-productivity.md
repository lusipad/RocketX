# `PERS` 个人效率

> 当前状态：`已实现`
> 基线：工作树 `2026-08-09`
> 平台：桌面端与网页版；下载记录的系统动作仅桌面端

## 1. 目标

把个人下一步行动、时间安排、联系人和已下载文件放在可预测的确定性界面中，支持 GTD 的组织与回顾，而不是要求用户从 AI 对话里寻找事实。

## 2. 范围

### 包含

- 手动待办的创建、完成、编辑、删除和失败回滚；
- 日历中聚合本地事项、ADO 工作和关联来源；
- Rocket.Chat 通讯录的分页、中文搜索和发起私聊；
- 桌面下载记录的查看、打开、定位和清除记录。

### 不包含

- 跨设备云同步本地待办和日历布局；
- 把日历视图写回外部日历服务；
- 网页版读取桌面文件系统或打开系统文件管理器；
- 让 AI 自行创建/删除个人事项而不经过对应确定性动作。

## 3. 入口与前置条件

- 顶部“待办”“日历”“通讯录”始终面向已登录用户。
- “下载”只在桌面端展示。
- 通讯录需要 Rocket.Chat 用户目录权限；ADO 日历项需要工作台连接。

## 4. 主流程

1. 用户在待办中捕获一个明确行动，保存后出现在当前用户的本地列表。
2. 用户完成、编辑或删除待办；持久化失败时界面恢复原状态并提示。
3. 日历按日期汇总可用来源，并允许用户回到待办、消息、PR 或 ADO 事实页。
4. 通讯录从 Rocket.Chat 分页加载用户，按用户名和显示名搜索，并可进入私聊。
5. 桌面端下载文件后写入记录；用户可打开文件、在文件管理器中定位，或只清除记录。

## 5. 状态与交互

- 待办：空、保存中、已保存、完成、持久化失败回滚。
- 日历：月份/日期选择、无事项、来源不可用和部分来源可用。
- 通讯录：加载、分页、搜索中、无结果、目录无权限。
- 下载：存在、文件已移动/删除、打开失败、记录已清除。

## 6. 平台与依赖

| 能力 | 桌面端 | 网页版 |
| --- | --- | --- |
| 待办 | 已实现；可使用桌面持久化命令 | 已实现；使用浏览器本地存储 |
| 日历 | 已实现 | 已实现 |
| 通讯录 | 已实现 | 已实现 |
| 下载记录列表 | 已实现 | 不适用 |
| 打开/定位本地文件 | 已实现 | 不适用 |

## 7. 数据与同步

- 手动待办、日历显示偏好等个人数据按 Rocket.Chat 服务器与用户保存在本机。
- 通讯录和用户状态以 Rocket.Chat 为真源，不把目录结果复制成独立联系人库。
- ADO/消息/PR 日历项只保存必要引用，源数据变化后以源系统为准。
- 下载记录保存路径、来源和时间；清除记录不删除磁盘文件。

## 8. 权限与安全

- 本地个人数据切换账号时必须隔离，不能把前一个用户的待办或下载记录展示给后一个用户。
- 打开/定位文件前使用已保存的明确路径，不允许消息内容拼接任意命令。
- 通讯录只显示当前 Rocket.Chat 账号有权查看的用户。

## 9. 失败与降级

| 场景 | 用户可见结果 | 副作用与恢复 |
| --- | --- | --- |
| 待办持久化失败 | 提示保存失败并恢复原状态 | 不保留只存在于界面的“幽灵待办” |
| ADO 日历源不可用 | 其他本地来源继续显示并标注 ADO 不可用 | 修复连接后刷新 |
| 用户目录分页失败 | 保留已加载用户并显示错误 | 重试当前页，不清空可信结果 |
| 下载文件已移动 | 显示文件不存在/无法打开 | 记录可清除，不删除其他文件 |

## 10. 验收标准

- `PERS-AC-01`：待办创建、更新、完成和删除在持久化失败时均回滚到最后可信状态。
- `PERS-AC-02`：不同服务器或账号不会共享个人待办、日历偏好和下载记录。
- `PERS-AC-03`：日历条目保留来源类型，并能回到可用的权威页面。
- `PERS-AC-04`：中文显示名可在通讯录搜索中命中并发起私聊。
- `PERS-AC-05`：清除下载记录不会删除磁盘文件；文件缺失时不会误报打开成功。

## 12. 已知差距与目标

- 本地待办与日历没有跨设备同步；若未来增加同步，必须先定义冲突、删除和账号迁移规则。
