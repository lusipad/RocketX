# `ONB` 首次引导、账号与连接

> 当前状态：`已实现`
> 基线：工作树 `2026-08-11`
> 平台：桌面端与网页版；首次理念引导仅桌面端新安装

## 1. 目标

让用户先理解 RocketX 的 GTD、注意力和“消息 / 工作台 / 管家”分工，再明确选择桌面通知与登录启动，最后以最少步骤连接团队 Rocket.Chat。团队可用 `rcx.workspace.json` 提供非敏感默认配置，个人凭据始终由用户单独填写。

## 2. 范围

### 包含

- 桌面端首次启动理念引导；
- 全新正式桌面安装的通知权限与登录启动默认选择；
- 从公开可访问 URL 或本地 JSON 加载团队配置；
- Rocket.Chat 服务器探活、用户名/邮箱与密码登录；
- 设置页预览、选择性导入和重新检查团队配置；
- 服务器或账号变化后的本地数据作用域切换。

### 不包含

- 从团队配置分发用户名、密码、PAT 或 AI 密钥；
- 代替 Rocket.Chat 完成注册、重置密码或多因素认证；
- 把首次引导是否完成同步到其他设备。

## 3. 入口与前置条件

- 正式桌面端没有任何 RocketX 本机状态时，登录页建立 `rcx-desktop-defaults-v1` 的 `fresh` 记录并进入首次引导。
- 已有用户升级且没有新记录时只迁移为 `legacy-migrated`，不读取或改写现有通知权限与启动项。
- 已有配置或完成首次引导后直接进入登录页。
- 设置页“团队配置”可随时从 URL 拉取、选择本地 `rcx.workspace.json`，或在 ADO 已配置后从受保护的 ADO Git 仓库读取同一配置文件。
- URL 配置必须无需交互登录即可读取；加入团队前配置必须包含 Rocket.Chat 地址。

## 4. 主流程

1. 用户阅读理念页，了解捕获、明确、组织和执行的分工。
2. 全新正式桌面安装进入“桌面体验”；通知与登录启动默认勾选，但在用户点击“应用并继续”前没有系统副作用。
3. RocketX 独立申请系统通知权限、写入并回读登录启动项；逐项展示结果，任一失败不阻断另一项或后续流程。
4. 用户选择加入团队，或跳过并进入个人设置。
5. 加入团队时，用户粘贴配置 URL 或选择本地 JSON。
6. RocketX 解析并展示 Rocket.Chat、ADO、模板、更新源等非敏感摘要。
7. 用户确认后，RocketX 先探活 Rocket.Chat，再应用配置默认值。
8. 用户在登录页填写 Rocket.Chat 账号和密码，连接成功后进入主界面。
9. 后续重新导入时，RocketX 展示字段差异；本地已修改字段默认保留，只有勾选项才写入。

## 5. 状态与交互

- `理念`：展示产品分工和继续/稍后设置动作。
- `桌面体验`：默认勾选系统通知与登录启动；应用时显示正在设置，完成后显示已开启、已跳过、未授权、不可用或失败，并允许单项重试。
- `等待配置`：接受 URL 或本地文件。
- `配置预览`：展示识别字段，不展示或读取个人凭据。
- `探活中/登录中`：禁用重复提交并显示当前阶段。
- `失败`：区分地址格式、服务器探活、配置解析、配置应用和认证失败。
- `已登录`：认证状态恢复后加载该服务器和用户作用域的数据。

## 6. 平台与依赖

| 场景 | 当前状态 | 行为 |
| --- | --- | --- |
| 正式桌面端首次安装 | 已实现 | 显示理念、桌面体验、团队连接三步引导，再进入登录 |
| 已配置或升级桌面端 | 已实现 | 迁移但不改系统现状；可从设置页重新导入或重跑引导 |
| Web / Debug | 已实现 | 不建立桌面默认记录，不读取或创建系统启动项 |
| 团队配置 URL 需认证 | 受限可用 | 当前不能完成交互认证，提示拉取失败 |

## 7. 数据与同步

- Rocket.Chat 服务器、引导完成状态、团队配置来源和已应用字段保存在本机。
- 桌面默认策略使用设备级、版本化记录，独立于 Rocket.Chat 账号；重跑引导、换账号和升级都不会重新应用系统默认。
- 团队配置可包含服务器、ADO 端点/认证类型、模板、更新源和层级布局等默认值。
- 服务器变化会使当前 Rocket.Chat 身份失效并要求重新登录。
- ADO 连接端点或认证类型变化时清除旧 PAT，防止凭据误用于另一个端点。
- 本地业务数据按 Rocket.Chat 服务器与用户隔离；引导状态也按来源规范化处理。

## 8. 权限与安全

- 配置文件不接受用户名、密码、PAT 或 AI 密钥作为团队默认值。
- 服务器地址必须是完整的 HTTP/HTTPS URL。
- 远程配置先预览后应用；设置页不会因检测到更新而静默覆盖用户本地修改。
- 登录凭据只提交到用户指定的 Rocket.Chat 服务器。
- 系统通知权限由操作系统保存，只有用户在桌面体验页点击继续时才请求；登录启动由系统插件写入并回读真实状态。

## 9. 失败与降级

| 场景 | 用户可见结果 | 副作用与恢复 |
| --- | --- | --- |
| JSON 损坏或缺少 Rocket.Chat 地址 | 显示配置不可读或缺失字段 | 不应用任何字段；修正后重试 |
| Rocket.Chat 不可达/协议不匹配 | 显示分类后的连接诊断 | 不完成首次加入；可修改地址 |
| 部分字段应用失败 | 显示应用失败 | 不宣称加入成功；重新打开预览确认本机状态 |
| 本地引导记录损坏 | 按未设置安全回退 | 重新显示需要的引导，不阻塞登录修复 |
| 桌面默认记录损坏或版本未知 | 按旧安装安全迁移 | 标记 `legacy-migrated`，不重新开启系统能力 |
| 通知拒绝或启动项写入失败 | 逐项显示未授权/失败 | 另一项继续执行；可单项重试或稍后到设置页处理 |
| 设备策略无法写入 | 不展示一次性系统默认；执行后写入失败则明确告警 | 不把当前会话误报为已持久化，可单独重试保存 |
| 团队配置后来变化 | 提醒有变化 | 只打开差异预览，不自动覆盖 |

## 10. 验收标准

- `ONB-AC-01`：全新桌面安装在无服务器和团队来源时显示理念引导，浅色与深色主题文字均保持可读；已有任一来源时不重复拦截。
- `ONB-AC-02`：远程或本地配置缺少 Rocket.Chat 地址时不能确认加入。
- `ONB-AC-03`：配置预览不出现个人密码、PAT 或 AI 密钥字段。
- `ONB-AC-04`：本地改过的字段在重新导入时默认不选中，用户明确勾选后才覆盖。
- `ONB-AC-05`：服务器地址变化后旧认证不能继续用于新服务器。
- `ONB-AC-06`：登录失败时保留用户可操作的服务器和账号输入，不进入主界面。
- `ONB-AC-07`：只有全新正式桌面安装显示并应用桌面默认；旧用户、重跑、换账号、Web 和 Debug 不覆盖系统现状。
- `ONB-AC-08`：通知与登录启动只在用户明确继续后独立执行并显示回读结果，单项失败不阻断进入应用。

## 12. 已知差距与目标

- 当前没有企业身份提供商或 MFA 的专用 UI；由 Rocket.Chat 登录能力决定。
- 远程团队配置只支持无需交互登录的地址；未来若支持受保护源，必须设计凭据范围和刷新策略。
- 首次引导的部分说明仍提到从团队配置设置 AI，但当前解析器会拒绝已移除的 AI 配置字段；后续 UI 文案应与本规格和解析器统一。
