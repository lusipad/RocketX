# `SCH` 已安排任务

> 当前状态：`部分实现`
> 基线：工作树 `2026-08-09`
> 平台：配置界面两端可见；可靠执行仅桌面端进程存活且 Codex 可用时

## 1. 目标

让用户把稳定、可重复的 Skill 工作流安排在本机定时运行，并能在同一页面创建、启停、立即触发和查看结果。当前能力是 RocketX 本机计划，不是云端常驻 Scheduled 服务。

## 2. 范围

### 包含

- 创建每日计划；
- 保存、搜索、筛选、启用、停用和删除计划；
- “立即运行”真实启动一次 Codex 自动化；
- RocketX 运行期间按分钟检查到期计划；
- 运行前轻量预检、Skill 启用检查和最近结果历史；
- 内置早/晚例行模板，默认关闭。

### 不包含

- 应用退出、电脑关机或休眠时继续执行；
- 云端跨设备调度、错过任务补跑或 SLA；
- 自动化运行中等待用户审批/表单输入；
- 当前创建 UI 中配置任意间隔（Store 支持不少于 15 分钟的间隔，但未形成公开创建流程）；
- 等同于 Codex/ChatGPT 官方“已安排”页面和云执行语义。

## 3. 入口与前置条件

- 管家侧栏“已安排”直接进入计划列表；“新建”在当前页面打开创建界面，不能跳回管家首页。
- 用户必须选择管家工作区，桌面端 Runtime/登录就绪，目标 Skill 已安装且启用。
- 自动触发要求 RocketX 页面/桌面进程保持运行，且性能模式关闭。

## 4. 主流程

1. 用户在“已安排”点击新建，填写名称、每日时间、目标 Skill 和任务指令。
2. 保存后计划留在当前页面，用户可启用/停用。
3. 用户点击“立即运行”，页面先做依赖检查，再创建独立 `app-server` 控制器和新 Thread 执行。
4. 自动触发时，本机调度器每 60 秒检查一次到期且启用的计划；轻量预检可在无新消息/提及时跳过 AI。
5. 运行完成或失败后记录摘要、时间和触发原因，页面可查看最近结果。
6. 自动化遇到需要人工输入的请求立即失败；遇到主机审批请求拒绝，不把无人值守任务挂住。

## 5. 状态与交互

- `已启用/已停用`：开关明确下一次是否进入到期检查。
- `运行中`：同一计划防止重复启动，立即运行按钮反馈当前状态。
- `已完成/失败/跳过`：结果区分成功、错误和预检无变化。
- `依赖不可用`：说明缺少工作区、Runtime、登录或 Skill。
- `最近结果`：每个计划最多保留当前实现规定的最近 10 条记录。

## 6. 平台与依赖

| 场景 | 当前状态 | 行为 |
| --- | --- | --- |
| 桌面端运行中 + Codex 可用 | 受限可用 | 可立即运行，并在应用存活时自动触发 |
| 桌面端退出/电脑休眠 | 不可用 | 不执行；当前无可靠补跑语义 |
| 桌面端无 Codex | 部分实现 | 可见/可保存计划，但执行失败并应显示依赖原因 |
| 网页版 | 部分实现 | 可见本机计划 UI，但当前没有可完成 AI Turn 的传输 |
| 性能模式 | 不适用 | 调度器和 AI 例行能力关闭 |

## 7. 数据与同步

- 计划、启停状态、版本与运行历史保存在当前设备的浏览器本地存储，键空间为 RocketX 例行任务作用域。
- 数据不跨设备同步；另一台电脑不会接管到期执行。
- 每次运行创建独立 Codex Thread，不复用交互式管家正在执行的控制器。
- 计划更新保留可回滚版本；历史结果不是业务系统真源。

## 8. 权限与安全

- 自动化固定使用“替我审批”类受控策略，不等待用户点击。
- Host approval 默认拒绝；普通/MCP 输入请求使运行失败。
- 计划中不得保存明文密码、PAT 或临时授权码。
- Skill 仍受工作区、网络和业务连接权限限制；计划启用不等于获得新权限。

## 9. 失败与降级

| 场景 | 用户可见结果 | 副作用与恢复 |
| --- | --- | --- |
| 工作区/Runtime/登录缺失 | 立即运行显示前置条件错误 | 不启动 Turn；修复后重试 |
| Skill 被停用/删除 | 显示目标 Skill 不可用 | 不改计划指令；重新启用或选择 Skill |
| 自动化请求人工输入 | 本次运行失败 | 不挂起后台；改造 Skill 为无人值守输入后重试 |
| 自动化请求主机审批 | 自动拒绝并失败或由任务处理拒绝结果 | 不越权执行 |
| 应用在触发时间未运行 | 当前不会执行 | 重新打开后不承诺自动补跑 |
| 计划到期前预检无变化 | 记录/显示跳过 | 不启动昂贵 AI Turn |

## 10. 验收标准

- `SCH-AC-01`：新建入口在“已安排”页面完成创建，不跳转到普通管家首页。
- `SCH-AC-02`：“立即运行”启动真实 Codex Turn，并把成功或失败结果写回当前计划。
- `SCH-AC-03`：启用计划只在 RocketX 存活时自动触发；文案不得承诺关机执行。
- `SCH-AC-04`：同一到期窗口不会重复运行同一计划。
- `SCH-AC-05`：缺少 Runtime、工作区、登录或 Skill 时展示具体依赖，不显示假成功。
- `SCH-AC-06`：无人值守运行遇到人工输入或审批时不会无限等待，也不会自动放开危险权限。
- `SCH-AC-07`：计划和历史明确标注“保存在此设备”，跨设备不互相覆盖。

## 12. 已知差距与目标

- 自动触发是页面内 `setInterval`，没有操作系统后台服务、唤醒或补跑能力。
- 网页版和无 Codex 场景目前仍能进入配置面，但无法执行；目标是入口即呈现真实能力状态。
- 创建 UI 只覆盖每日时间，Store 的间隔触发不是完整产品流程。
- 需要真实短周期验证：立即运行、下一分钟到期、失败记录、重复抑制、应用退出不执行和重新打开后的明确状态。
