## 第三批：原生 Codex 同项工作现场（本机控制切片验收通过）

本批把第二批合同接入真实工作入口：`ButlerPage → WorkKanbanBoard → WorkCardPortal → NativeCodexWorkScene`。继续复用原工作、原会话记录 ID 和原 `acp` 来源标记；交接只改变 Host 所有权和绑定版本，不创建替代会话。属于 W03–W06 的纵向切片，不关闭这些父包的全部验收。

- `butler_native_runtime.rs` 在 Rust 持有持续连接、持久命令消费、原端事件、决定与工作快照；UI 通过五个原生工作 IPC 提交意图、接续原会话、回答、撤回排队和读快照。
- `acp.rs`、`local_sessions.rs`、`proc.rs` 绑定原 profile、CODEX_HOME、账号、设备、工作目录和一次性交接授权。版本和 app-server 探测每次限 3 秒、双流各 64 KiB；标准 npm/pnpm shim 解析原安装的真实 Codex 程序，未知 wrapper 拒绝，不隐式启动另一份 Node/Codex。
- 复用原 `dispatch_actions` 保存 Resume/Prompt/Steer/Interrupt。先持久认领，再执行原生 I/O；重试先核对原始 requestId 输入，旧代际重试不产生新副作用。未知投递不重发，Interrupt 需同一原生轮次的结束事实才完成。
- 原生消息按原端 item/turn 身份合并。完成事件即使早于 RPC 回执、或导入历史超过 20 轮，也保留足够事实完成关联。原端返回错误 thread/cwd 时不开控制能力。
- 问题和批准绑定原轮次、要求与绑定版本；回答前持久保留发送归属，未发送可恢复、未知不重放。连续决定和断线先到的回执不能把待处理/未知覆盖成运行中。额外权限请求当前只支持拒绝。
- `nativeWorkOwnership.ts`、`superAgentBridge.ts`、`workSupervisor.ts`、`workLedger.ts` 排除旧 ACP/Pi 派发与扫描覆盖；同一实例内旧/新入口共享 writer 门禁。正常停止核对本次 owned 进程树；父进程意外退出不能证明子进程结束时保留占用，不复用 PID 盲杀。
- 同页现场保留草稿、中文输入法、发送目标、立即调整/排队区别、撤回和原位决定；停止显示真实回执，结束一轮不等于整项工作已验收。附件保留在草稿，本切片尚不发送附件。
- 实机截图复核还发现原 page 布局把输入框挤出首屏；浏览器边界检查在旧实现中复现 1280×800 下输入底部 y=1051。已将原生 Codex page 改成剩余高度现场，阅读、决定和队列共用一个滚动区，输入固定底部；工作要求同页折叠，待决定固定提示一键定位且不抢焦点。1280×800、940×640 在长消息、展开要求及新增审批后通过输入/按钮边界检查；390px 无横向溢出。非 Codex 和其他页签布局保持。最终独立 Tauri 包在两种真实窗口通过 8 组边界/可点击检查。
