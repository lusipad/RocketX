# 管家完整对话双栏布局计划

## 1. 最可能调整的决定

### 桌面使用“会话历史 + 当前对话”双栏

- 左栏宽度 236px，直接展示已持久化的普通管家会话，最近更新在前。
- 右栏只承载当前会话：标题与动作、消息滚动区、底部输入。
- **Confidence: high**
- **What would flip it:** 如果管家会话未来不是用户可管理对象，而只是任务的内部运行投影，
  应改成任务列表而不是会话列表。

### 输入框始终固定在当前对话底部

- 成果、在办、消息、审批和过程都进入同一个可滚动区域。
- Composer 不参与消息滚动，使用带明确占位文案的输入面板。
- **Confidence: high**
- **What would flip it:** 如果产品要求输入随最后一条消息出现，需要重新定义“阅读历史”和
  “继续输入”的优先级；当前反馈明确要求随时可输入。

### 历史通过会话列表浏览，不新增日期翻页

- 复用 `useButler.sessions`、`switchSession` 和既有持久化，不建立第二套历史索引。
- 列表显示名称、最后一次提问和相对时间；列表自身滚动。
- **Confidence: high**
- **What would flip it:** 如果“翻页”明确指单个超长会话的服务端分段加载，需先扩展持久化协议；
  当前仓库只有本地 session registry，没有远端分页契约。

### 窄屏回落为单列

- 839px 以下隐藏历史侧栏，在对话头部保留紧凑会话选择器。
- 消息滚动区和底部 Composer 的结构不变。
- **Confidence: high**
- **What would flip it:** 如果移动端也必须同时看到历史，可再设计抽屉，不在本轮引入。

## 2. 假设

- `useButler` 是会话、消息、运行态和持久化的唯一来源；来自当前代码，置信度高。
- 普通会话已按 `updatedAt` 排序，workflow 会话不会出现在用户历史列表；来自当前代码，
  置信度高。
- 用户参考 Codex 的核心是信息架构和输入可发现性，不是复制 Codex 的项目树与任务执行轨迹；
  来自本轮反馈，置信度高。

## 3. 偏离策略

- 遇到布局边界问题时选择可逆、最小影响的 CSS/组件调整，并记录在实现笔记中。
- 不修改 session 数据结构、持久化协议、审批语义或 AI 运行链路。
- 如果发现现有 session registry 无法表达历史，或必须迁移用户数据，停止并重新确认。

## 4. 机械工作（低评审价值）

- 新增纯展示的会话历史组件。
- 调整 `ButlerConversation` 的外壳、头部、滚动区和 Composer。
- 放宽对话视图在 `ButlerPage` 中的宽度限制。
- 更新 Playwright 会话切换断言和视觉快照。

## 5. 验证

- 1440px 与 2048px：左侧历史可见，当前项高亮，右侧 Composer 始终在视口底部。
- 切换、新建、重命名、删除继续使用现有 store 并保持消息隔离。
- 768px 与 390px：无横向溢出，会话选择和 Composer 均可见。
- 视觉判定达到 90 分；回归、UI、类型检查和生产构建全部通过。
