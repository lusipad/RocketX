# AI 管家个人工作代理改造计划

> 文档状态：**历史实施计划**。旧“对话/委托/定时任务”导航和二级 Memory 管理入口不是当前合同；现状见[管家任务](specs/butler-tasks.md)、[已安排任务](specs/scheduled-tasks.md)和[Memory](specs/memory.md)。

## 目标

把 AI 管家从“自成一套工作系统”收敛为随处可调用的私人工作代理，并让产品级“今天”承接用户自己的消息、待办、日程和工作对象。

## 已确认决策

- 管家默认进入对话，不再默认进入主动工作驾驶舱。
- 管家一级导航只保留“对话 / 委托 / 定时任务”。
- 用户待办与管家委托在状态模型和界面上分开。
- 记忆、技能、连接与权限保留为二级管理入口。
- 现有审批、暂停、恢复、运行记录、来源和持久化数据全部保留。
- 原“工作台”改为全局“今天”，即使未连接 Azure DevOps 也可使用。

## 第一切片

1. 重排全局导航并开放“今天”概览。
2. 重做管家顶层信息架构与默认入口。
3. 拆分个人待办与委托运行的投影模型。
4. 更新回归和 UI 测试，执行类型检查与定向验证。

## 偏差策略

- 不删除旧“今日纸”视图，日历或已有入口仍可显式打开。
- 不在本切片迁移持久化结构；先通过兼容视图完成渐进改造。
- 如测试暴露跨模块耦合，仅修复与本切片直接相关的边界，不顺带重构相邻代码。

## 验收标准

- 点击全局“管家”直接进入可对话界面。
- 管家主界面不再出现六项纵向子导航。
- “委托”只展示真正交给管家执行的运行，不混入普通待办。
- “今天”在未配置 ADO 时仍展示本地待办、日程和消息摘要。
- 记忆、技能、连接与权限仍可访问。
- 相关回归、类型检查和 UI 流程通过。
