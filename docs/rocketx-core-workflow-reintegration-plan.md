# RocketX 核心工作闭环重新整合计划

状态：待实施  
前置切片：`docs/butler-personal-agent-restructure-plan.md`  
实施记录：`docs/implementation-notes-rocketx-core-workflow-reintegration.md`

## 1. 最可能需要调整的决策

### 1.1 路线选择

已比较以下方案，成本是相对量级，不是排期承诺。

| 方案 | 做法 | 核心代价 | 粗略成本 | 结论 |
| --- | --- | --- | --- | --- |
| A. 只改文案 | 继续保留现有页面，只统一命名 | 入口和对象仍然重复，无法解决心智负担 | 数小时 | 拒绝 |
| B. 只精简管家 | 保留全局导航和 Today 工作台，只继续收管家菜单 | 已完成第一切片，但两套“今天”仍互相竞争 | 1–2 天 | 不足以解决问题 |
| C. 保留能力、重整表面 | 收敛顶级意图，重新归属现有能力，不迁移数据 | 需要调整导航、Today 和兼容入口 | 3–5 天 | **采用** |
| D. 新建独立 Activity 中心 | 照搬 Slack 的 Today / Activity / Slackbot 三页 | 会新增一个用户概念，和现有消息过滤重复 | 1 周以上 | 拒绝 |
| E. 重写任务与管家领域 | 同时统一 Todo、ADO、委托、定时任务的数据模型 | 风险和回归面过大，不适合候选版本前 | 2 周以上 | 拒绝 |

选择 C 的依据：用户已经明确认可“消息负责沟通、今天负责定向、管家负责执行”的三意图模型；当前底层模块、Store 和导航已解耦，大部分能力可以通过重新归属而不是删除实现减法。

**Confidence：high**  
**What would flip it：** 如果真实使用数据证明待办、日历或联系人是绝大多数用户的独立高频起点，而不是 Today 或消息流中的上下文动作，则保留相应顶级入口。

### 1.2 已核验的前提

| 前提 | 结论 | 证据 | 对实施的影响 |
| --- | --- | --- | --- |
| “当前问题是功能表面过多” | **确认** | `NavRail.tsx` 当前有消息、今天、待办、日历、下载、管家、通讯录等分区；设置另占固定入口 | 顶级导航必须做减法，不能只改管家 |
| “今天已经是统一定向页” | **不成立** | `WorkbenchPage.tsx` 仍保留工作项、PR、构建、自定义查询标签和收藏夹，本质仍是改名后的工作台 | Today 要重做职责，不只是改标题 |
| “管家已经没有重复的 Today” | **不成立** | `ButlerPage.tsx` 仍保留 `now` 分支、主动工作驾驶舱、Composer、需关注与建议 | 旧今日纸必须退出可见产品表面 |
| “做减法必须删除底层功能” | **不成立** | 模块由运行时注册，UI Store 只保存模块标识；隐藏导航不等于删除 Store 或数据 | 候选版本前优先隐藏、迁移入口，避免数据迁移 |
| “需要新增 Activity 页面” | **不成立** | `UIState.convFilter` 已有未读、@我、收藏、私聊等消息过滤 | 复用消息模块承担分诊，不新增模块 |
| “待办和管家委托仍是同一对象” | **已在前置切片修复** | `ButlerWorkspaceModel` 已拆成 `delegations` 与 `personalTasks` | 保持领域边界，不再在 UI 重新混合 |

### 1.3 顶级信息架构

主导航只表达三个稳定用户意图：

```text
消息      谁在和我沟通，哪些消息需要处理
今天      我有没有漏掉什么，今天应该关注什么
管家      帮我弄清楚，或把事情做掉
```

设置继续固定在底部，但不算工作意图。其他模块不删除：

```text
待办      → Today 中的待办区、全局搜索、上下文深链
日历      → Today 中的日程区、全局搜索、上下文深链
下载      → 消息附件入口、全局搜索
通讯录    → 发起会话、全局搜索
ADO 详情  → Today 条目钻取、全局搜索或对象深链
```

`MODULE_ORDER` 可以继续保留隐藏模块，确保快捷键、持久化状态和既有深链兼容；`NavRail` 只显示三个核心入口。

**Confidence：high**  
**What would flip it：** 如果全局搜索目前不能可靠打开隐藏模块，则第一切片先增加一个统一“更多工具”入口，而不是直接让能力失联。

### 1.4 对象的唯一归属

| 对象 | 唯一权威归属 | 其他位置只允许做什么 |
| --- | --- | --- |
| 消息、@我、未读、线程回复 | 消息 | Today 只展示少量 Highlights 并返回消息来源 |
| 个人待办 | 待办 Store；主要呈现在 Today | 管家可建议创建，确认后写入；委托页不得展示 |
| 日程 | 日历 Store；主要呈现在 Today | 管家可准备会议；不得复制成管家任务 |
| ADO 工作项、PR、构建 | ADO Store / 原系统 | Today 只投影“为什么今天需要看”；详情使用钻取页 |
| 管家委托 | Butler Errand | Today 只展示等待用户或失败的委托；完整生命周期在委托页 |
| 定时任务 | Routine | Today 只展示失败或需要处理的运行；配置和历史在定时任务页 |
| 记忆、技能、连接、权限 | 设置 | 管家对话可以链接过去，但不作为一级或常驻二级导航 |
| 今日纸 `now` | 退役的兼容标识 | 既有调用迁移到 Today；历史生成能力可继续服务摘要和通知 |

**Confidence：high**  
**What would flip it：** 如果某类 Butler 主动发现无法在 Today 中表达来源、原因和动作，则暂留内部兼容模型，但仍不恢复可见 `now` 页面。

### 1.5 Today 的产品合同

Today 只回答：“我有没有漏掉什么，现在可以继续推进吗？”它不是管理后台，也不承载完整对象列表。

固定结构：

1. **建议关注**：最多展示少量、可解释的优先事项；每项都有“为什么现在出现”、来源和下一步。
2. **今日日程**：展示当天安排，并提供“让管家准备”或打开日历。
3. **重要动态**：只放可能漏掉的消息、失败运行、待确认委托；处理后可消失。
4. **待办**：展示逾期和今天到期事项；完整列表通过钻取打开。

不再常驻展示：ADO 标签栏、自定义查询、完整 PR/构建列表、收藏夹、管家 Composer、技能或连接状态。ADO 与管家仍可以给 Today 提供信号，但不能夺走页面结构。

**Confidence：high**  
**What would flip it：** 如果现有队列无法稳定给出“为什么现在出现”，先保留确定性排序和来源，不用未经验证的 AI 排序替代。

### 1.6 消息承担 Activity，而不是新增 Activity

消息模块现有“未读 / @我 / 收藏 / 私聊”等过滤承担分诊。实施只需要：

- 在消息入口与过滤区明确“需要处理”的状态；
- Today 的重要动态必须返回对应消息，而不是在 Today 内完成长对话；
- 不新增一个 Activity 模块，也不复制通知 Store。

**Confidence：high**  
**What would flip it：** 如果消息过滤无法容纳应用通知和管家事件，事件仍留在 Today/管家角标，不为此创建新顶级页面。

### 1.7 管家的产品合同

管家默认进入对话，只保留三个工作视图：

```text
对话       理解、搜索、研究、起草，以及发起一次委托
委托       查看明确交给管家的异步执行
定时任务   查看重复执行、状态、最近结果和失败原因
```

调整边界：

- 移除可见 `now` 页面；旧入口改为打开 Today 或带上下文进入对话。
- “记忆与技能”“连接与权限”迁移到设置，不再占据管家导航的“更多”。
- 对话空态只展示真实工作场景，例如“总结我错过的”“准备下一场会议”“找出需要跟进的事项”。
- 只有明确委托才创建 Errand；普通问答、摘要、起草不自动成为委托。
- 执行继续遵守“草案/确认 → 运行 → 需用户 → 完成/失败”，保留来源、步骤、停止和审批。

**Confidence：high**  
**What would flip it：** 如果记忆或连接需要频繁在对话中切换，保留一个指向设置对应区域的快捷链接，而不是恢复完整管理页。

### 1.8 首次引导与文案

首次引导从“捕获、理清、组织、回顾、执行”的系统方法，收敛为用户能立即复述的三个动作：

```text
在消息里沟通
在今天里确定重点
把复杂工作交给管家
```

AI 引导不罗列模型、技能、记忆和连接器，改为在消息、日程、PR、文件等上下文给出单一动作。首次打开管家时使用具体示例，不展示能力目录。

**Confidence：medium**  
**What would flip it：** 如果首次配置必须解释 Rocket.Chat 与本地 AI 的安全边界，安全说明保留，但放在三动作之后。

### 1.9 Slack 参考语义：保留、适配、舍弃

只借鉴产品语义，不复制 Slack 代码、视觉或品牌。

| 参考行为 | 计划 | 原因 |
| --- | --- | --- |
| Today 负责定向、Activity 负责分诊、Agent 负责行动 | **保留** | 是减少心智负担的核心分工 |
| AI 能力出现在消息、线程、日程和文件上下文 | **保留** | 减少复制粘贴和找入口 |
| 答案有来源，执行有步骤、停止和确认 | **保留** | 符合 RocketX 的可信执行原则 |
| 独立 Activity 页面 | **适配**为消息过滤 | 现有能力已覆盖，不新增概念 |
| Slackbot Tasks | **适配**为委托与定时任务 | RocketX 已有两种不同生命周期 |
| Enterprise Search / Salesforce 数据结构 | **舍弃**为 IA 前提 | 连接器可以存在，但不决定用户表面 |
| Slack 的具体导航、品牌与视觉 | **舍弃** | 我们借鉴职责，不做产品克隆 |
| 为每个 AI 能力建立独立页面 | **舍弃** | 与本次减法目标冲突 |

## 2. 假设

| 假设 | Confidence | 来源 |
| --- | --- | --- |
| 用户认可“三意图”模型，并授权按此开始整合 | high | 本轮及上一轮对话 |
| 候选版本前应保持现有本地数据、审批和执行记录兼容 | high | 现有发布上下文与前置计划 |
| 隐藏模块仍应可通过搜索或上下文深链访问 | high | 保留能力、减少表面的产品原则 |
| 不需要在本轮改 Store 持久化格式 | high | 当前导航与 Store 已解耦 |
| Today 的第一版优先采用确定性规则，不依赖新的 AI 排序 | medium | 降低候选版本风险的保守默认 |
| 移动端也采用同一信息架构，不保留额外主入口 | medium | 产品一致性默认；需 UI 验证 |

## 3. 偏差策略

遇到边界问题时，选择可逆、最小影响、最接近“三意图”模型的方案，并立即记录到实施记录。

可以继续推进而不暂停：

- 为保留深链而暂留内部 view/type 标识；
- 将暂时无法迁移的低频入口放入全局搜索或设置；
- 保留底层 Store、生成器和历史数据，只移除可见页面；
- 视觉细节采用现有样式系统中的最简单组件。

必须停止确认：

- 需要删除或不可逆迁移用户数据；
- 需要扩大 AI、连接器或桌面端权限；
- 发现“三意图”模型会让已有核心能力完全无法触达；
- 同一实施阶段出现第三个计划偏差，说明地图已经失真。

## 4. 机械实施工作（低审阅价值，可按计划执行）

### 切片 0：锁定行为

- 为当前模块迁移、隐藏模块深链、管家审批和 Today 本地数据补回归断言。
- 记录导航、Today、管家宽屏与移动端基线。

### 切片 1：收敛全局导航

- `NavRail.tsx` 只保留消息、今天、管家三个工作入口。
- 保留设置固定入口；待办、日历、下载、通讯录转入搜索/上下文入口。
- 统一模块顺序、快捷键与持久化迁移。
- 更新 `FirstRunPage` 为三动作模型。

### 切片 2：让 Today 真正负责定向

- 复用现有 Todo、Calendar、消息、ADO、Butler 投影，不创建第二套领域数据。
- 移除 Today 常驻 ADO 标签栏、自定义查询和收藏夹。
- 形成“建议关注 / 今日日程 / 重要动态 / 待办”四区。
- 每个聚合项保留来源和明确的上下文动作。
- ADO 完整列表改为钻取页或搜索深链。

### 切片 3：退役管家内部 Today

- 从可见管家视图中移除 `now` 分支和第二套 Composer。
- 将旧 `openButlerPaper` 调用迁移到 Today 或带来源的管家对话。
- 迁移需关注、建议、失败运行到 Today 的重要动态。
- 删除本切片产生的孤儿样式、组件和测试夹具；底层历史生成能力按需要保留。

### 切片 4：把管理能力放回设置

- 将记忆、技能、连接、权限统一放入设置的管家区域。
- 管家页面只提供轻量深链，不再渲染完整管理面板。
- 复用现有消息、PR、日历来源跳转，让 AI 在上下文出现。

### 切片 5：统一文案与清理兼容层

- 全局只使用“今天 / 管家 / 委托 / 定时任务 / 待办”五个稳定名称。
- 移除“工作台、今日纸、主动工作驾驶舱、例行照看”等可见旧概念。
- 删除已无调用的兼容视图；如果仍有深链调用，保留重定向并记录。

## 5. 验证

### 可观察产品行为

- 新用户在一分钟内可以复述：“消息里沟通，今天里确定重点，把复杂工作交给管家。”
- 桌面主导航只有消息、今天、管家三个工作入口；移动端结构一致。
- 未配置 ADO 时 Today 仍完整可用；配置后 ADO 只是信号来源，不改变页面骨架。
- Today 首屏不出现完整工作项、PR、构建、自定义查询、收藏夹或管家 Composer。
- 点击 Today 条目可以回到唯一来源或把带上下文的工作交给管家。
- 点击管家默认进入对话；管家可见导航只有对话、委托、定时任务。
- 普通待办不会进入委托；问答和摘要不会自动创建委托。
- 记忆、技能、连接和权限可从设置访问，但不占据管家工作导航。
- 所有旧 `today`、`ai-assistant`、`now` 入口有兼容迁移或明确重定向。

### 工程验证

- Web 类型检查和生产构建通过。
- 全量回归测试通过。
- 导航、Today、管家、消息分诊和设置的 UI 流程通过。
- 宽屏、窄屏、明暗主题没有横向溢出或不可达入口。
- `git diff --check` 通过；差异只触及本计划直接相关文件和由改动产生的孤儿。

实施时持续更新 `docs/implementation-notes-rocketx-core-workflow-reintegration.md`：
