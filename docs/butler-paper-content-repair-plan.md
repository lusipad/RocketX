# 管家纸面真实内容修复计划

## 决策

- **Keep**：保留“等你点头 / 在办 / 今天 / 临时问答”的单页结构、760px 阅读列和安静空纸。
- **Adapt**：把现有 `useTodos` 的未完成待办直接投影到今日纸面；纸面不再把“没有派活或 AI 简报”等同于“没有事情”。
- **Drop**：删除“管家纸不展示普通待办”的旧假设。左侧待办数量和纸面内容必须来自同一份数据。
- 待办区最多直接显示 5 项，按截止日优先、其后按创建时间倒序；剩余项用一个小按钮进入完整待办页。
- 每项只提供完成按钮、标题和必要元数据，不复制编辑器，不增加卡片墙，也不新增 store。
- 每日整理尚未完成时显示轻量加载状态；失败时显示原位错误和重试按钮。已有内容不因整理失败而消失。

## 假设

- 左侧“待办 1”代表当前账号真实存在 1 条未完成待办，管家页应至少让它可见。
- 历史纸仍是只读快照；实时待办只投影到今天，不改写过去日期。
- 本轮只补齐已经证实缺失的待办数据和 rounds 状态，不扩展日历、工作台或新的推荐内容。

## 偏差规则

- 如果现有待办数据无法稳定排序或完成，先修数据合同并补回归，不在组件里做临时副本。
- 如果视觉空间不足，优先减少展示条数和元数据；不隐藏整段真实内容。
- 发现其他数据源缺口时记录证据，本轮不静默扩大范围。

## 实施

1. 为 `ButlerPaperViewModel` 增加未完成待办投影和稳定排序。
2. 先补纯回归与 UI 回归，证明“有待办时不能渲染空纸”。
3. 在 `ButlerPage` 增加紧凑待办区、完成按钮、查看全部入口，以及 rounds 加载/失败反馈。
4. 更新旧的“纸面不展示待办”断言和设计说明。

## 验证

- 纯回归：完成项被过滤，截止日优先，无截止日按新到旧，历史纸不泄露实时待办。
- UI：种入 1 条待办后，管家页显示标题且不出现空状态；完成后恢复真正空纸。
- 类型检查、Web 构建、定向 Playwright 均通过。
- 本地桌面版重启后，使用真实账号数据截图并执行 visual-verdict，目标不低于 90/100。
