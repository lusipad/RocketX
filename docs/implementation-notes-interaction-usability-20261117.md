# 实施记录：交互可用性修正

计划：`.omx/plans/interaction-reset-20261117.md`。用户明确反馈交互不好用；本轮以当前代码走读和可点击流程校准，不以测试数量代替可用性结论。

## 决定

- 先改不依赖整体外观选择的操作断点：单条旧会话有直接打开/继续入口；发送稳定、立即调整作为单次显式动作；当前可回答问题先于长历史；已有回复可原位读取并复用 Markdown，不能把模型自述当验证通过。
- 整体交互用 A 管家简报、B 工作对话、C 成果审阅三种独立原型比较；建议 B 为当前工作主线，A 提供总览，C 用于审阅。原型明确全模拟，不计为产品能力或用户认可。
- 本轮仅 Web 与对应验证，不改原生控制、数据库、权限或真实应用，不启动 Cargo，不使用真实 Key/会话，不写外部平台。

## 偏离

产品 Portal 的 Codex 导航额外做了一行文案修正：把「成果与验证(n)」改成「验证记录(n)」，避免与原位查看回复的「查看成果」同义。非 Codex 保持原文案；没有改变执行能力。

## 发现

- `WorkKanbanBoard::createConversation` 与 `ButlerPage` 把新交代切成 conversation surface，旧工作则进入 WorkCardPortal；有位置感断裂。
- `WorkSessionImport` 以加入所选/当前范围为主，单条继续需多步。
- `NativeCodexWorkScene` 运行时有持久队列/调整模式，Enter 与主按钮含义会随模式变化；决定位于历史之后，成果按钮默认跳到可能为空的验证页。
- 受保护用户程序尚未替换，不能假设用户正在看的界面就是最新源码。

## 待观察

用户实际最卡手的一步和三个方向的偏好尚未收到；已用一个异步问题征询，不阻塞上述可逆改动。大范围新旧工作统一仍须实际能力链路支持，不能仅换入口就宣称管家已会自主委派。

## 已实现与简化

- `apps/web/src/components/WorkSessionImport.tsx`：单条直接「打开工作」，复用已有身份、账号与幂等关联；不会启动执行。选择框与范围加入只在「批量整理」后出现。扫描边界和冷接续说明按需展开。
- `apps/web/src/components/NativeCodexWorkScene.tsx`：移除持久发送模式；Enter 和主按钮始终发送，运行中默认排队。「立即调整」仅把当前文本发送给冻结的当前轮次；停止仍等待实际回执。
- 当前可回答请求从长历史中独立出来，正文单独滚动、提交栏占真实空间；超长说明按需展开。未知与旧请求仍禁用，不重复提交。
- 回复复用现有 Markdown；没有验证记录时「查看成果」原位定位最近回复，明确标记未核验。有验证记录时仍打开真实记录页。
- `apps/web/src/components/WorkCardPortal.tsx`：仅 Codex 验证标签澄清；`apps/web/src/styles.css`：仅既有原生现场小节布局规则。
- 对应 UI 文件：`tests/ui/work-session-import.spec.ts`、`tests/ui/native-work-scene.spec.ts`、`tests/ui/work-first-detail.spec.ts`。未增加依赖或另一套执行抽象。

## 后续交互决策：控制看板优先

用户在“可以直接控制多项工作”的前提下接受 Kanban 主界面建议，优先级覆盖此前 B 工作对话为主的建议。目标为四列控制看板＋顶部管家简报＋同页工作对话/成果，保留 RocketX 现有视觉风格。方案第4节与 WBS W06.01 同步修改；此为方向确认，不代表新原型已获用户认可或生产实现已完成。

可点击片段为线程目录的 `rocketx-work-control.html`，全部模拟；原有对照片段保留。宽窗展开详情时保持看板列与卡片位置，窄窗自然堆叠；问题在卡片直接回答，开始/停止等模拟结果返回后才变更列，工作草稿独立保留。未改产品运行时、数据库或原生合同。

原型浏览器检查：双主题、1024/940/736/390/320宽度共10组，加完整操作旅程共11组通过；实际覆盖卡片答复、等待开始/停止确认、默认排队、单次调整、切工作草稿、新事草稿收起恢复、同页成果与不改变路由。`.omx/logs/kanban-control-20261117/verification.json` 保留结果，配套截图与脚本同目录。宿主 wrapper 预置三项允许的静态 CDN 资源，未出现额外业务请求。

中途真实发现新建模拟工作一直停在待开始：`setWidgetState` 同步回传持久快照，替换了定时器引用的工作对象。模拟动作未结束时不重载外部快照，终态统一保存后恢复接收；修后完整旅程重新通过。该修正只针对原型状态，没有冒充后台持久执行实现。
