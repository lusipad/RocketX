# AI 管家好用性系统框架（五层委托模型）

写于 2026-07-25。回答一个问题：**「管家怎么样才算好用、现在差在哪、按什么顺序补」**。
与 [`ai-design.md`](ai-design.md)（对账员：管家做什么）的分工：本文是好用性的**评价体系与迭代地图**，
不改变产品定位。与 [`m12-implementation-plan.md`](m12-implementation-plan.md) 的关系：架构 phase 必须
在本文的层上找到坐标，答不出「改善哪层判据」的切片往后排。

## 0. 第一性原理：管家是一种委托

管家类产品的本质是**委托**：用户把注意力和任务交给它。委托成立当且仅当——

> **委托成本（表达 + 等待 + 澄清 + 验证）< 亲自做的成本，且结果可信。**

「不好用」没有玄学，只有委托在某一层失败。四个已确认痛点（2026-07-25 用户裁决）就是
四种失败形态。理论原点：Horvitz《Mixed-Initiative UI》(CHI'99) 描述理想系统的比喻正是
**"an intuitive, courteous butler"**——偶尔提有价值的建议、注意到你忙就不打扰、以最小干扰退场。

## 1. 五层模型

下层是上层的地基；每层有一句话定义、可裁决的判据、理论依据、现状与缺口。

### L0 信任契约——「敢不敢委托」

- **定义**：能力边界清晰（它能干什么、不会干什么）、副作用可控、错了能纠。
- **判据**：用户能一句话说出管家能/不能干什么；副作用 100% 过确认卡（注入测试钉死）。
- **理论**：HAX G1/G2（说清系统能做什么、做得多好）；PAIR「心智模型」「可解释性+信任」；
  Lee & See 信任校准（已在 ai-design.md）。
- **现状**：**架构强、呈现弱**。审批卡/审计/只读沙箱/「大脑没有手」是架构级卖点；
  但「管家能干什么」没有呈现面——用户不知道该问什么，就永远只问试过的三件事。
- **缺口→行动**：能力面呈现（空状态/输入框提示随场景轮换七场景例句；技能列表即菜单）；
  **边界一句话声明**（Slack 启示：信任边界本身是产品特性——「只读你能读的，动手必先问你」
  写进管家空状态，管家比 Slack AI 更严的架构值得被看见）。

### L1 单次交互经济学——「一次委托值不值」

- **定义**：成本侧 = 延迟、表达成本、澄清来回；收益侧 = 结论质量（可直接行动 vs 素材堆）。
- **判据**：分段耗时可测且 P95 达标（P95 才是体验真相）；七场景「结论直接可用」比率。
- **理论**：Horvitz ①增值自动化（比亲自做强才有资格存在）⑤对话解澄清要计打扰成本
  ⑧精度随不确定性优雅降级（**做少而对 > 做多而错**）；业界实践：结论有固定模板
  （飞书群总结三段式：核心摘要/关注要点/待办；邮件 AI 分诊 = 行动+草稿，从不给素材列表）。
- **现状**：**痛点 1+4 所在层**。七场景一半停在素材层（比较 PR 无结论层、找承诺靠人工）；
  延迟无测量（spike 工具往返一整轮 ~7.2s，是否常态未知）。
- **缺口→行动**：①链路分段计时（线程建立/首 token/工具往返/整轮），按 P95 看；
  ②结论层技能：每场景写死输出模板（比较 PR = 差异/风险/先看哪个；找承诺 = 谁/事/期限/原文链接）。

### L2 记忆与连续性——「第 N 次委托比第 1 次便宜」

- **定义**：不用重复交代（长期记忆）、调查可挂起可恢复（会话连续）、越用越懂你。
- **判据**：同一件事重复交代次数趋零；隔天回来能接着上次继续。
- **理论**：Horvitz ⑪维护近期交互的工作记忆 ⑫观察中持续学习；业界：Claude 每 24h 自动合成
  对话记忆 + Projects 按 scope 隔离 + **记忆访问透明可见**（贴合本项目审计取向）；
  ChatGPT saved memories + 后台整理。
- **现状**：**痛点 3 所在层**。单 session + 3 天 TTL 截断；记忆有骨架（别名/偏好/承诺）
  但靠显式 `remember`，无自动合成。
- **缺口→行动**：P1（多 session/transcript/去 TTL）+ 薄版自动合成（session 收尾把要点写进
  记忆，下次自动带上；scoped memory 完整版仍在 P5）；记忆引用透明化（「我记得你说过 X」可点看来源）。

### L3 主动性——「不委托它也在干活」

- **定义**：感知 → 判断（该不该说）→ 时机（何时说）→ 方式（怎么说）。
- **判据**：简报条目「值得看」比率（反馈数据，不是自我感觉）；管家页连续被无视天数归零。
- **理论**：**v3 已吃透的一层**——Horvitz ②目标不确定性 ③注意力状态定时机 ④期望效用
  ⑦坏猜测代价最小化；LookOut 三档行为（置信不足→静默；中→带证据问；高→做并可撤销）；
  警报疲劳/SRE 分层/bounded deferral（均已在 ai-design.md 附录）。业界：Pulse 夜间异步研究、
  晨间卡片；Slack Recap 用户自圈范围（AI 不全猜）。
- **现状**：**痛点 2 所在层，但骨架是对的**。对账循环/提议制/打断权阶梯/静音双保险已上线；
  死穴在：三赌注（判断力/台账负担/薄输入价值）一直没被真实使用数据裁决——没有反馈回路，
  信噪比永远靠猜。
- **缺口→行动**：依赖 L4 的反馈机制拿到数据后日拱一卒调对账技能；不新增攻坚工程。

### L4 成长闭环——「明天比今天好用」

- **定义**：反馈进系统、行为可见地改变、同样的错不犯第二次。
- **判据**：同类负反馈重复出现次数趋零（纠一次就改）；用户能看到「管家学到了什么」。
- **理论**：HAX 第四组（over time：从行为学习、渐进个性化、更新要告知）；Horvitz ⑫；
  业界标杆 = Pulse 三件套：**每条可反馈（值/不值）+ 负反馈立即生效（dismiss 明天就不出）+
  curate（用户直接说关心什么，一句话进判断标准）**。
- **现状**：**最大空洞**。唯一通道是「少来这种」→ `remember` 静音；无 per-item 反馈、
  无 curate、学到的东西不可见。这层空着，其他四层的问题都只能靠猜着修。
- **缺口→行动**：简报三件套（每条 值/不值 一键、负反馈即时生效、curate 一句话写进对账
  技能判断标准）；「管家学到的」在工作日志可见。

## 2. 依赖律与修复顺序

```
L4 成长闭环   ←—— 改进引擎：没有它，每层的修复都靠猜
L3 主动性     ←—— 没人打开应用就没有简报观众
L2 连续性     ←—— 单次都不值，累积无从谈起
L1 单次经济学 ←—— 委托的第一次成功体验
L0 信任契约   ←—— 一切的前提（本项目已最强的一层）
```

两条定律：**下层不牢，上层白搭**（L1 不行→没人用→L3 无观众→L4 无数据）；
**L4 是横切引擎**（每层的裁决判据都需要它供数）。

因此修复顺序 = **L1 + L4 先行**（单次体验快胜 + 装上反馈引擎），L2 随 P1 落地，
L3 用 L4 数据日拱一卒，L0 呈现层收尾补齐。

## 3. 四痛点坐标（2026-07-25 用户全选裁决）

| 痛点 | 层 | 根因 | 解法（已列入行动） |
|---|---|---|---|
| 问答没结论 | L1 收益侧 | 场景无结论模板，输出素材堆 | 结论层技能（固定模板） |
| 慢/摩擦大 | L1 成本侧 | 无测量，P95 未知 | 分段计时→按大头动刀 |
| 对话不连续 | L2 | 单 session + TTL 截断，无自动合成 | P1 + 薄版记忆合成 |
| 简报不值得看 | L3（裁决靠 L4） | 三赌注无数据，反馈通道单一 | 简报三件套反馈 |

## 3.5 交互地图：一次委托的五个环节（横切视图）

五层判据落到界面上的形态。每环节标注归属波次；未排波的按「用户可见变化条款」排队。

| 环节 | 从 | 到 | 归属 |
|---|---|---|---|
| ① 发起 | 打开管家页打字描述一切 | 消息/PR 右键携上下文直达（「提取这段的承诺」）；空状态轮换七场景例句；`/ai` 保留 | 待排（Slack 启示 ②③） |
| ② 等待 | 工具调用期间静止无感 | 工具动作实时可见（「正在读 #212 第 3 个文件…」）；深调查「我去查，好了叫你」异步化 | 可见化待排；异步化随 P1 |
| ③ 接收 | 自由文本 | 固定三段式 + 每条结论内联原文/PR 链接（引用即产品） | 第一波 |
| ④ 行动 | 结论后动作自理 | 结论上长一键动作（转待办/盯它/打开 PR），平移 v3 简报一键动作机制；拟稿永过确认卡 | 待排（机制现成） |
| ⑤ 调教 | 仅「少来这种」静音 | 每条 值/不值 + curate 一句话 + 工作日志「记住了：…」 | 第二波 |
| ⑥ 回归 | 回来面对断掉的历史，重新进入状态靠自己翻 | recap「上回说到」（2026-07-25 用户点名，对标 Claude Code）：打开管家给三段——你走开的这段（世界增量，合流巡视简报）/ 我们手头的事（各 session 状态）/ 建议先做（一键继续）；恢复单个调查 session 时开头一段「上回说到」而非甩历史 | **P1 的用户可见交付**（依赖 transcript + session 要点自动合成） |

## 4. 裁决机制（两周节奏）

每两周对五层判据各打一次分（用户 dogfooding 自评 + L1 计时数据 + L4 反馈统计）：

- 翻身线：连续一周「每天至少一次问管家比自己翻快」+「简报每天真的点开」。
- 不达线：继续按最低分层迭代，**不回架构铺路**（架构切片必须挂到某层判据上才准动工）。

**用户可见变化条款（2026-07-25 用户裁决追加）**：每个切片规格必须先写「用户可见变化」
一节——用最终用户第一人称、前后对比的 demo 脚本描述交付后打开应用能看到/感受到什么。
写不出来的切片必须显式标注「地基工程，用户无感」，并说明它服务于哪个后续可见变化；
一个波次里纯地基切片不得多于一半。

## 5. 研究依据（补 ai-design.md 附录未含的）

- Horvitz 12 原则全貌（CHI'99）：①增值自动化 ②目标不确定性 ③注意力定时机 ④期望效用推断
  ⑤对话解澄清计打扰成本 ⑥高效直接调用与终止 ⑦坏猜测代价最小化 ⑧精度优雅降级
  ⑨协作精化结果 ⑩社会得体行为 ⑪近期交互工作记忆 ⑫观察中持续学习。
- Microsoft HAX 18 条（CHI'19，haxtoolkit）：四组 = 初见设预期 / 交互中贴情境 / 出错时可纠 /
  长期会学习——正好对应 L0/L1/L4。
- Google PAIR Guidebook 六章：用户需求+成功定义、数据+评估、心智模型、可解释性+信任、
  反馈+控制、错误+优雅失败。
- 业界实现对标（2026-07 调研）：ChatGPT Pulse（异步简报 + 三件套反馈）、Slack Recap
  （用户圈范围）、Superhuman/Shortwave（分诊固定结构 + Daily Brief）、Claude Memory
  （24h 自动合成 + scope 隔离 + 访问透明）、飞书群总结（三段模板）。
