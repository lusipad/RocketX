# 管家设计语言统一计划

## 1. 最可能调整的决定

### 决定一：以 RocketX 主壳为基础，不为管家创建第二套主题

- 全局导航、管家导航、会话历史和主工作区共用现有主题变量。
- 管家只保留“头像与在线状态”作为人格识别，不使用独立渐变背景、装饰性光效或另一套品牌色。
- **Confidence:** high
- **What would flip it:** RocketX 后续将管家拆成独立产品或独立窗口。

### 决定二：建立四种表面层级

| 层级 | 用途 | 视觉规则 |
|---|---|---|
| Base | 主工作区 | 页面底色，不加边框 |
| Subtle | 二级导航、会话历史 | 与 Base 轻微区分，使用单侧分隔线 |
| Raised | 输入框、可操作面板 | 细边框、小圆角 |
| Selected | 当前导航、当前会话 | 同一强调色浅底，同一文字强调 |

- 卡片只用于可操作对象，例如技能、成果、会话和输入容器。
- 纯说明、档案字段、分组内容使用标题、分隔线和留白，不再套卡。
- **Confidence:** high
- **What would flip it:** 用户明确要求所有内容都保持卡片式仪表盘。

### 决定三：统一字号与密度

| 角色 | 字号 | 字重 |
|---|---:|---:|
| Page title | 20px | 650 |
| Section title | 16px | 650 |
| Body / navigation | 14px | 400–600 |
| Supporting text | 12px | 400 |
| Metadata | 11px | 400–500 |

- 页面不再同时出现 24–36px 的宣传式标题和 11–12px 的工具文本。
- 页面标题、正文、说明文字在所有管家页面保持相同层级。
- **Confidence:** high
- **What would flip it:** 管家档案被重新定义为营销式人物首页。

### 决定四：统一形状与状态

- 控件圆角：6px。
- 卡片与输入容器圆角：8px。
- 头像保持圆形。
- Hover、Selected、Focus、Disabled 在所有导航和按钮中复用同一状态语言。
- 主要动作每个区域最多一个实心强调按钮，其余使用文本或描边按钮。
- **Confidence:** high
- **What would flip it:** RocketX 主壳先整体迁移到另一套组件库。

### 决定五：统一内容网格

- 管家普通页面使用同一内容起点和最大宽度。
- 对话页允许会话历史 + 对话工作区结构，但标题、工具栏与输入框对齐同一主轴。
- 宽屏增加可读留白，不拉伸正文；移动端只保留一个主内容列。
- **Confidence:** medium
- **What would flip it:** 真实数据证明宽屏需要常驻第三上下文栏。

## 2. 假设

- 当前管家页面继续嵌入 RocketX 主应用，而不是独立应用。来源：现有产品结构，信心高。
- 当前深色与浅色主题都必须保留。来源：现有 UI 测试，信心高。
- 用户此前认可技能卡片布局，因此技能列表继续使用卡片。来源：用户反馈，信心高。
- 本轮不改变导航信息架构、数据模型和业务流程。来源：本轮范围，信心高。

## 3. 偏差策略

- 遇到现有组件无法完全套用统一规则时，选择可逆、CSS 优先、最小影响的方案并记录。
- 不新增依赖，不建立新的主题运行时，不重写已有组件库。
- 如果需要改变导航信息架构、数据持久化或交互语义，停止并重新确认。

## 4. 机械工作

低审查价值，由实现者直接执行：

- 归拢现有 Butler CSS 变量和重复色值。
- 统一导航、标题、按钮、表面、分隔线、圆角和文字颜色。
- 修正桌面与移动端内容宽度和间距。
- 更新受影响的视觉快照。

## 5. 验证

- 浅色和深色桌面截图中，主壳、管家导航、会话历史和主内容表现为同一产品。
- 身份页、技能页、今日页和对话页使用同一字号、颜色、圆角与状态规则。
- 390px 移动端无横向溢出，正文与控件不低于既有可用性标准。
- `visual-verdict` 达到 90 分以上。
- UI 测试、回归测试、类型检查与构建通过。

## Handoff

实现过程记录在 `docs/implementation-notes-butler-design-language.md`。出现偏差时优先选择可逆、CSS 优先、最小影响的方案；第三个偏差出现时重新运行 kickoff。
