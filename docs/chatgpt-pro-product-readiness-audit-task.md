# ChatGPT Pro 工程任务：RocketX 产品级可交付成熟度审计

## 你的角色

你是 RocketX 的外部首席工程师。本轮只做基于真实源码的产品级成熟度审计和可执行交付分解，不直接提交代码。Codex 总负责人负责独立验证你的事实、决定优先级，并把后续相互独立的实现切片分别交给独立对话完成。

源码包是当前脏工作区的文本源码快照。你不能访问本地私有仓库、内部 Rocket.Chat、Azure DevOps、真实用户数据或凭据。不要把 README、计划文档、测试名称或候选实现默认视为已完成事实；必须沿实际入口、调用链、持久化和测试证据核对。

## 产品目标

把 RocketX 收敛为一个完整、完备、可交付的成熟产品：

- 以 Codex App Server 协议和 Codex 原生能力为核心，而不是在外层再造一套 Agent Router、Skill Runtime 或沙箱。
- 高度集成 Rocket.Chat 和 Azure DevOps Server，用户以自然语言聊天为主，复杂工程任务少量派给 Codex。
- 产品体验类似“持续在线的个人助理 / 管家”：理解上下文、记住承诺、发现待处理事项、可恢复、可审计、离线时明确降级，不无限等待。
- Skill 使用 Markdown `SKILL.md`，既可内置、用户可编辑，也可通过界面发现和市场安装；支持自然语言和 `$skill` 显式触发。
- Business MCP 负责让 Codex 无感访问业务系统，但默认只读；高风险写入由 Host 的 typed action + 显式确认 + 幂等/并发保护执行。
- 架构分层稳定、边界清楚，未来新增业务系统或 Skill 不需要复制管家核心。
- Windows 桌面安装、升级、卸载、离线、诊断和发布证据达到真实交付标准。

## 不可破坏的架构边界

- 不修改 Rocket.Chat Server。
- 不把 PAT、Token、Cookie、密码或系统凭据暴露给模型、Skill 文本、日志、checkpoint 或审计 UI。
- Codex 原生能力优先；Host 只保留 UI、上下文/凭据注入、业务 MCP 生命周期、typed confirmation、持久化和产品策略。
- Business MCP 的通用工具保持 GET-only/read-only；不得开放任意 URL、任意方法或通用 PATCH。
- 写操作必须区分草案、审批、执行、回读和恢复；不能把 mock 或本地状态更新称为远端成功。
- 离线或依赖不可用时必须快速、明确、可恢复地结束，不允许无限 loading、静默重放或后台无界重试。
- 不新增依赖、不大规模重构、不推倒已有稳定分层，除非审计能证明现有边界本身不可交付；本轮只提出，不修改。
- 当前另有独立对话审查 ADO 工作项状态受控写入；本轮只把它作为产品能力矩阵的一项，不重复写补丁。

## 必须审计的产品面

1. **产品入口与对话体验**
   - 管家是否真以自然语言为主，动作按钮是否只在必要时出现；
   - 对话流、进度、澄清、失败、恢复、长任务和 Codex dispatch 是否形成完整闭环；
   - 是否仍残留含糊或工具台式概念（如无法解释的“成果”）。
2. **Codex App Server 协议集成**
   - 实际协议入口、thread 生命周期、审批、工具事件、断线恢复、版本兼容和官方能力边界；
   - 是否存在 mock/spike 被误当生产入口，或并行 runtime/router。
3. **Rocket.Chat 集成**
   - 登录、消息/线程/讨论、搜索、附件、未读、mentions、待办来源、发送幂等、离线缓存和真实权限；
   - MCP/Host/直连职责是否一致，是否会泄露认证头或跨作用域数据。
4. **Azure DevOps Server 集成**
   - Work Items、PR、Build、Saved Query、身份、过程模板、NTLM/PAT、MCP 只读和 typed writes；
   - 超时、并发、幂等、回读、权限文案、账户切换和 Server 2022 兼容。
5. **Skill 与市场**
   - 内置 Skill 质量、数量、重复/无效 Skill、Markdown 合同、`$` 触发、自然语言触发、用户编辑、安装/更新/卸载、离线缓存、来源信任和插件边界；
   - Memory 是否应作为 Skill/持久化能力提供，当前实现与目标差距。
6. **个人助理连续性**
   - Profile、Memory、Todo、Commitment、Today、Routine、Errand、Watcher、长期线程和跨重启恢复；
   - 哪些是生产链，哪些仍是 UI/测试/计划占位；是否会误报完成。
7. **安全与信任边界**
   - 凭据、SSRF、业务 MCP 参数白名单、敏感路径、附件、日志/审计、prompt injection、用户确认和真实副作用；
   - 依赖与锁文件、Tauri 权限、外部进程、脚本调用和升级渠道。
8. **可靠性、离线与可观测性**
   - 有界超时、取消、重试、崩溃恢复、checkpoint、SQLite/localStorage 一致性、错误分类、诊断包和用户可理解状态；
   - 离线模式是否真正可用，市场/业务系统不可达时是否无感降级。
9. **可测试与交付门禁**
   - lint/typecheck/unit/contract/regression/UI/E2E/build/Cargo/安装包/升级卸载/发布资产；
   - 区分字符串源码断言、mock 消费者测试、真实本地 E2E 和生产验证；识别虚假的“已验证”。
10. **产品文档和发行**
    - README、architecture、blueprint、roadmap/vision/changelog（若存在）与真实实现是否一致；
    - 安装配置、离线、权限、故障排查、升级/卸载和发布证据是否足以让第三方交付。

## 研究方法

- 先绘制真实运行入口与层次：UI → Host/store → Codex/App Server/MCP → Rocket.Chat/ADO → persistence/native。
- 对每个能力标记：`production-complete`、`implemented-but-unproven`、`partial`、`spike/mock-only`、`absent`。
- 结论必须引用路径和符号；重要缺口需要给出可触发链和用户影响。
- 用测试反向核对生产入口；只检查源码文本的测试不能证明运行时行为。
- 识别计划文档早于/晚于源码导致的漂移，不把计划当交付。
- 优先删除重复层、无效 Skill 和含糊 UI，不用新增抽象掩盖问题。

## 交付物

请生成一个可下载的 `ROCKETX_PRODUCT_READINESS_AUDIT.md`，至少包含：

1. 一页执行摘要：当前是否可交付、最危险的 5 个事实、最强的 5 个已完成能力。
2. 真实架构图（Mermaid）和每层职责/禁止事项。
3. 上述 10 个产品面的证据矩阵：状态、源码证据、测试证据、缺口、风险。
4. “声明 vs 事实”清单：README/计划/UI 声称与实际入口不一致处。
5. 安全与副作用审计：秘密、只读/写边界、确认、幂等、恢复和超时。
6. 交付门禁矩阵：现有命令、覆盖层级、是否安全离线运行、缺失门禁。
7. 按价值和依赖排序的 P0/P1/P2 backlog。每项必须是可独立交付的切片，包含：
   - 用户可见结果；
   - 允许修改范围与不可破坏边界；
   - 明确验收标准；
   - 必跑测试；
   - 风险和前置依赖；
   - 推荐交给单独 ChatGPT Pro 对话的任务边界。
8. 推荐的前三个实现切片。优先选择能让产品从“能演示”跨到“可交付”的最小集合，不以代码量排序。
9. 明确列出仍需真实环境验证的事项，不能把 mock/静态结论说成生产验证。

本轮不要提供大而全的重写补丁。若发现一个会造成秘密泄露、数据丢失或越权写入的 P0，可附一个单独的最小建议 diff，但必须清楚标为“建议，未由 Codex 验收”。
